# Автообновления GradeBookAI (сайт · телефон · десктоп)

> Цель: выпустил обновление → оно **само подтягивается с `https://esstu-gradebook.ru`**,
> без «удалить старое / скачать новое» вручную.

Ключевая идея: приложение на телефоне — это **веб-бандл в нативной обёртке** (Capacitor).
Поэтому 99% изменений (перенос фич с десктопа/сайта = HTML/JS/CSS) можно доставлять
**по воздуху (OTA)** — подменять веб-часть без переустановки APK. Полный APK нужен
только когда меняется **нативное** (новый плагин, разрешение, версия SDK).

---

## 1. Сайт (web) — уже авто-обновляется
Это живой сайт: задеплоил новую версию → пользователь получает её при следующей загрузке.
`sw.js` версионирует кэш (`VERSION`) и чистит старый при обновлении.
- **Доделать (опц.):** тост «Доступна новая версия — обновить», когда service worker
  увидел новый билд (`updatefound` → `skipWaiting()` → `location.reload()`).
- Скачивать/удалять ничего не нужно.

## 2. Телефон (Capacitor APK) — два уровня

### 2a. OTA веб-бандла (основной путь, 99% обновлений)
Инструмент: **`@capgo/capacitor-updater`** (ядро open-source, **self-hosted** — раздаём с
нашего сервера, ничего платного/чужого не нужно).
- **Выпуск:** `npm run build` → упаковать `dist` в zip → выложить на сервер:
  `/app/bundles/<webVersion>.zip` + манифест `/app/latest.json`
  `{ webVersion, url, checksum(SHA-256), minNativeVersion, mandatory }`.
- **Клиент:** при старте/резюме плагин читает `latest.json` → если `webVersion` новее →
  скачивает zip (в фоне) → применяет при следующем запуске (или сразу с перезагрузкой
  WebView). Пользователь видит свежую версию, **ничего не удаляет**.
- Оффлайн — проверку пропускаем, работаем на текущем бандле (наш offline-слой готов).

### 2b. Обновление APK (редко — при нативных изменениях)
OTA меняет только веб-слой. Если поменялось нативное (плагин/разрешение/SDK) — нужен APK.
- Выложить `/downloads/GradeBookAI.apk` + `/app/apk-info.json` `{ nativeVersion, url }`.
- Клиент сверяет `nativeVersion`; отстал → экран «Доступна новая версия приложения» →
  скачать APK (`@capacitor/browser` / FileTransfer) → открыть системный установщик
  (нужно разрешение «Установка из неизвестных источников»).

### Как различать OTA vs APK
Храним два номера: **`webVersion`** (бандл, растёт часто) и **`nativeVersion`** (растёт
редко). В `latest.json` — `minNativeVersion` для этого бандла. Логика на старте:
```
if (device.nativeVersion < manifest.minNativeVersion)  → предложить обновить APK (2b)
else if (manifest.webVersion > current.webVersion)     → тихий OTA веб-бандла (2a)
else                                                    → всё актуально
```

## 3. Десктоп (.exe) — контекст (источник фич)
Свой авто-апдейтер: при старте проверяет `/app/desktop-info.json` `{ version, url }`;
новее → качает новый `.exe` с `esstu-gradebook.ru`, заменяет и перезапускается.
Уже есть `/desktop-info` (раздаёт установщик) — расширить до версии + автозамены.
Отдельная задача, можно позже.

---

## 4. Серверная часть (esstu-gradebook.ru)
Статика за Caddy **или** эндпоинты FastAPI:
- `GET /app/latest.json` — манифест OTA (webVersion, url, checksum, minNativeVersion, mandatory).
- `GET /app/bundles/<ver>.zip` — веб-бандл.
- `GET /app/apk-info.json` + `/downloads/GradeBookAI.apk` — нативные обновления.
- Всё по HTTPS (есть) + SHA-256 checksum (целостность), опц. подпись.

## 5. CI/CD — «выпустить обновление» одной кнопкой
Скрипт релиза: `build → zip dist → scp на VPS → bump webVersion в latest.json`.
(Позже — GitHub Actions: push в ветку → сборка сайта+бандла+APK → деплой.)

## 6. Безопасность
- Только наш домен по HTTPS; проверка SHA-256 бандла перед применением.
- Откат: плагин Capgo умеет откатываться на предыдущий бандл, если новый «не завёлся»
  (не вызвал `notifyAppReady()`) — защита от «кирпича».
- APK — подписан release-ключом (иначе Android не поставит обновление поверх).

## 7. Оценка объёма
- **2a (OTA веб-бандла):** ~1 день — плагин + манифест/хостинг + скрипт релиза + проверка на старте.
- **2b (APK-fallback):** ~0.5 дня — манифест + экран «обновить приложение» + установщик.
- **1 (тост на сайте):** ~1–2 часа.
- **3 (десктоп):** отдельно, ~1 день.

## 8. Что решить перед стартом
- OTA-движок: **Capgo self-hosted** (рекомендую) vs собственный (WebView.setServerBasePath — больше кода).
- Обязательные обновления (`mandatory`) — блокировать вход до обновления или нет.
- Где хостить бандлы: статикой Caddy или через FastAPI.
- Нужен ли release-подписанный APK уже сейчас (для 2b он обязателен).
