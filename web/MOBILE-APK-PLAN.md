# GradeBookAI Mobile (Android APK) — подробный план

> Цель: телефонное приложение с **дизайном веб-версии** (мобильная вёрстка Vue),
> функционалом уровня десктопа, **online-first + оффлайн-доступ**: часть данных
> сохраняется локально и видна без интернета; при появлении сети — обновляется.

---

## 0. Голосовой ввод в веб-версии — есть ли он?

**Ответ: на фронте — НЕТ, на сервере — уже готово (заготовка).**

- Сервер (`server/app/routers/web.py`): реализованы два эндпоинта, помеченные
  «ЗАГОТОВКА»:
  - `GET /web/vector/stt/status` → `{"available": <bool>}` — прямо в докстринге:
    *«по этому флагу веб-клиент показывает/прячет кнопку микрофона»*;
  - `POST /web/vector/stt` — принимает аудио из браузера (`getUserMedia`/
    `MediaRecorder`), распознаёт **на ХОСТЕ** (faster-whisper) и возвращает текст.
- Веб-фронт (`web/src`): **ни одной строки** про голос/микрофон/STT
  (`endpoints.js` знает только `vector.ask`). Кнопки микрофона нет.

Итого: логика «хост включил STT → у всех появляется кнопка» на бэкенде уже есть —
не хватает только UI. Как включить — см. §5.

## 1. Как работает ДЕСКТОП (эталон архитектуры)

- **Offline-first ядро.** Источник данных — локальная **SQLite** (`core.DBManager`).
  UI читает и пишет локально мгновенно; сеть не в критическом пути.
- **Синхронизация.** Фоновый `sync_runner` + `sync_engine` делают `push`/`pull` к
  серверу. Инварианты: метку времени **LWW ставит сервер**; удаления — «надгробия»
  (tombstones); конфликты оценок не затираются. Таблицы: `users, groups, subjects,
  lessons, grades, config` (`SYNC_MODELS`).
- **Роли** (студент/преподаватель/админ), единый вход, **персистентная сессия** по
  токену (перезапуск не требует пароля).
- **Барьер устройства**: десктоп — строгий (чужой ПК не тянет всю БД); веб — снят
  для всех ролей (защита: креды + анти-брутфорс + HTTPS + role-scoped `/web/*`).
- **Голос**: faster-whisper на хосте, админ включает в настройках Вектора, клиенты
  получают кнопку записи. Команды преподавателя (оценка) всегда подтверждаются.

## 2. ВЕБ-версия и её мобильный дизайн (что уже есть)

- Стек: **Vue 3 + Vite + Tailwind v4**, дизайн-токены портированы 1:1 из десктопа.
- **Адаптив** (телефон): сайдбар — выезжающий drawer; шапка со сплошным акцентом;
  компактный заголовок страницы; статы в 2 колонки; таблицы со скроллом; Вектор —
  маскот фоном + чат-оверлей + «фокус-режим» (при вводе маскот гаснет, чат на всю
  высоту, чтобы клавиатура не перекрывала интерфейс).
- **PWA**: `manifest.webmanifest` + `sw.js` уже есть → приложение устанавливается
  на телефон. НО service worker кэширует **только оболочку** (index.html + ассеты),
  а **данные `/web/*` — никогда** (комментарий в sw.js: «живые данные/ПДн»).
- **Модель данных сейчас — online-first**: каждый экран при открытии делает GET
  `/web/*`; локального кэша данных нет → **офлайн экраны пустые**. Это и есть
  главный разрыв, который закрываем (§4).

## 3. Как собрать APK — **Capacitor** (обёртка веб-приложения)

Почему Capacitor: берёт собранный `dist/` и кладёт в нативный Android-WebView →
**дизайн в приложении 1:1 совпадает с мобильным вебом** (то, что просили). Даёт
доступ к нативным возможностям через плагины (хранилище, статус сети, микрофон).

Шаги:
```
cd web
npm i @capacitor/core @capacitor/cli @capacitor/android
npx cap init "GradeBookAI" ru.esstu.gradebook --web-dir dist   # appId можно изменить
npm run build
npx cap add android            # создаёт папку android/ (нативный проект)
npx cap copy android           # кладёт свежий dist в проект
cd android && ./gradlew assembleDebug   # → android/app/build/outputs/apk/debug/app-debug.apk
```

Тулчейн на этой машине:
- **Node** ✅ (v24), **JDK 17** ✅ (Adoptium, `JAVA_HOME` задан).
- **Android SDK** ❌ — нужно поставить (cmdline-tools + platform + build-tools,
  ~2–3 ГБ, принять лицензии). Без него `gradlew` не соберёт APK.

Настройки нативной обёртки: `server.androidScheme=https`; для запросов к боевому
серверу — либо один origin (как на вебе), либо разрешить cleartext только для dev.
Нативные плагины по мере надобности: `@capacitor/preferences` (хранилище),
`@capacitor/network` (онлайн/офлайн), `@capacitor/app`, иконка/сплеш через
`@capacitor/assets`.

## 4. OFFLINE-FIRST для мобилы (ключевое требование)

Схема **stale-while-revalidate**: показываем сохранённое, при сети — обновляем.

**Фаза A — оффлайн-чтение (делает приложение полезным без сети):**
1. Слой кэша поверх axios-интерсептора (`api/client.js`): каждый **успешный** GET
   `/web/*` сохраняем в локальное хранилище (Capacitor **Preferences** на телефоне /
   IndexedDB в браузере), ключ = `метод+URL+логин`.
2. Ошибка сети на GET → отдаём последнее сохранённое тело (+ флаг `stale: true`).
3. Индикатор в шапке: «Офлайн — показаны сохранённые данные» (у нас уже есть
   онлайн/офлайн-точка — расширим её на этот случай).
4. Токен уже персистится (localStorage) → **офлайн пользователь остаётся в аккаунте**
   и видит кэшированные Главную/Журнал/Статистику/Расписание.

**Фаза B — оффлайн-записи (ближе к десктопу, опционально):**
5. Очередь мутаций: POST/PUT/DELETE (оценка, занятие, CRUD) при офлайне кладём в
   локальную очередь и помечаем данные как «ожидает синхронизации».
6. При появлении сети очередь **воспроизводится** тем же контрактом (`/web/teacher/
   grade`, `/web/admin/*`), сервер ставит **LWW-метку** — конфликты разрешаются как
   в десктопе. Это уже почти паритет с offline-first десктопа.

Что кэшируем в фазе A: `student/overview|journal|stats`, `teacher/overview|journal|
students|stats`, `admin/overview|teachers|students|groups|subjects`, `schedule`.
НЕ кэшируем: `/auth/*` (только сеть), пароли/ПДн сверх того, что роль и так видит.

## 5. Голосовой ввод — включить в вебе/мобиле (бэкенд готов)

1. `endpoints.js`: добавить `vector.sttStatus()` (GET `/web/vector/stt/status`) и
   `vector.stt(blob)` (POST `/web/vector/stt`, multipart).
2. `VectorDock.vue` / `VectorPage.vue`: при `sttStatus().available === true`
   показать кнопку 🎤. Запись — `navigator.mediaDevices.getUserMedia({audio})` +
   `MediaRecorder` → Blob → POST → полученный текст в поле ввода (дальше как обычный
   вопрос). Поведение 1:1 с десктопом: кнопка есть, только если хост включил STT.
3. В Capacitor: разрешение `RECORD_AUDIO` в `AndroidManifest.xml` + запрос доступа.

## 6. Рекомендуемый порядок

1. **Оффлайн-чтение (Фаза A)** — сразу закрывает «работает без интернета».
2. **Capacitor-обёртка + Android SDK → debug-APK** — получить ставящийся файл.
3. **Голосовой ввод** — небольшая задача, backend готов.
4. Иконка/сплеш/имя/подпись (keystore) → **release-APK**.
5. **Оффлайн-записи (Фаза B)** — полный паритет с offline-first десктопа.
