# GradeBookAI: глобальный план паритета «Desktop = Web»

> Цель: довести **Web Edition** (`web/`) до полного функционального, визуального и
> «безопасностного» соответствия **Desktop Edition** — минус Speech-to-text (согласовано).
> Критерий готовности: любой сценарий, который админ/преподаватель/студент делает в
> десктопе, он может сделать и на сайте, с теми же цифрами (единый `grading.py`), тем же
> Вектором и тем же уровнем защиты ПДн.
>
> Общий сервер и общая БД. Веб пишет в те же таблицы и id-форматы, что синк десктопа
> (`sync_engine`), поэтому изменения ходят в обе стороны. Метку LWW ставит сервер.
>
> Статус: Pre-Release-2.8 (монорепо). Легенда: ✅ готово · 🟡 частично · 🔴 нет.

## Phase 0 — Реальные данные (ФУНДАМЕНТ, без этого всё пусто) 🔴

Сейчас на VPS почти нет аккаунтов/оценок: авто-синк десктоп→сервер должен пушить всех
студентов/преподавателей + оценки, чтобы на сайте было что показывать.

- [ ] Довести `sync_runner`: гарантированный логин админа-хоста и первый полный push
      (после фикса «пустого пароля» и flush на выходе — проверить на живом стенде).
- [ ] Пуш студентов/преподавателей/групп/предметов/занятий/оценок (`collect_local` →
      `/sync/push`), верификация: они видны в `/web/admin/*`.
- [ ] «Здоровье синка» в админке (последний успешный push/pull, счётчики) — и десктоп, и сайт.
- **Готово, когда:** любой заведённый в десктопе аккаунт логинится на сайте и видит свои данные.

## Phase A — Экраны-витрины (READ) добить 🟡

- [ ] Все срезы, что есть в десктопе: student overview/journal/stats; teacher journal/

## Phase B — Запись/CRUD (ядро журнала) 🟡→✅

Серверные write-эндпоинты (роль-скоуп, валидация, id-форматы §10, метка LWW сервером):
- [x] `POST /web/teacher/grade` — оценка/посещаемость.
- [x] CRUD студентов, групп, предметов (`/web/admin/*`).
- [ ] **Занятия (lessons) CRUD**: создать/править/удалить пару (тип, №, тема, дата,
      пересдачи) — иначе журнал нельзя наполнить с нуля на сайте.
- [ ] **CRUD преподавателей** (+ назначение предметов/групп нагрузки).
- [ ] **Полноценный журнал-редактор** (порт `teacher_dashboard`): пересдачи
      (`<lid>_retake[_N]`), темы занятий, массовое проставление, «средний» пересчитывается
      сервером после каждой правки.
- [ ] Экспорт журнала/списков в **xlsx** (сервер отдаёт файл, кнопка на странице).
- **Инвариант:** всё пишем в те же таблицы → десктоп подхватывает pull. Формулу оценок
      не дублировать (единый `grading.py`).

## Phase C — Вектор 1:1 🟡→✅

- [ ] Полный набор интентов, как в десктопе (`vector/intents`): средний, долги, пропуски,
      оценки по предмету, справка о ВСГУТУ/колледже, списки (для персонала), сравнение и т.д.
- [ ] **LLM-озвучка**: `privacy.anonymize` (ФИО→«Студент №N») → GigaChat/Ollama → `deanonymize`.
      На сервере (РФ-IP) — GigaChat; ключи в `.env`, НЕ в git. Нет LLM → шаблоны (как сейчас).
- [x] Маскот реагирует эмоцией по `intent`+`mood` (30 спрайтов, порт `emotes.pick`).
- [ ] **Проактивные insights-карточки** на дашбордах (порт `vector/insights.py`): «есть
      долг по…», «средний вырос/упал», «завтра пара в 8:30».
- **Инвариант анти-галлюцинаций:** цифры только из SQL, LLM лишь переформулирует.

## Phase D — Расписание препода + UX 🔴

- [ ] **Расписание преподавателя по ФИО (пункт 2):** серверный ленивый парсинг

- [ ] **Реалтайм**: мониторинг и оценки обновляются без перезагрузки (polling/SSE).
- [ ] Напоминания о ближайших парах (порт `schedule/reminders`).

## Порядок и почему

1. **Phase 0** — без реальных данных сайт пустой (это блокер всего).
2. **Phase B** — ядро журнала (занятия + журнал-редактор + преподы + xlsx).
3. **Phase C** — Вектор как фишка продукта (LLM + insights).
4. **Phase D** — расписание препода (пункт 2) + чарты + реалтайм.
5. **Phase E** — дизайн под эталон.
6. **Phase F** — безопасность записи + автопубликация.
