# Кого убивать первым при нехватке памяти

На машине 1 ГБ памяти и 2 ГБ свопа. Если память всё же кончится, ядро убьёт процесс с
наибольшим «весом»: размер плюс поправка `OOMScoreAdjust`. Поправки расставлены так, чтобы
первыми гибли фоновые задачи, а журнал и вход на сервер — последними (27.10.2026).

| служба | поправка | почему |
|---|---|---|
| сводка, сторож уязвимостей, учения | +500 | разовые задачи: повторятся при следующем запуске |
| ssh | −200 | сам демон крошечный и почти не выбирается; сессии наследуют поправку, поэтому не ниже журнала — тяжёлая команда в консоли не должна пережить журнал |
| сторож тревог | −200 | должен успеть написать, что случилось |
| Caddy | −300 | без него сайт не открывается снаружи |
| журнал (`gradebook`) | −500 | главное, ради чего машина живёт |

Установка — drop-in файлы из этой папки:

```bash
for s in gradebook caddy ssh; do
  install -D -m 644 deploy/maintenance/oom/$s.conf /etc/systemd/system/$s.service.d/20-gradebook-oom.conf
done
systemctl daemon-reload   # действует со следующего старта службы
```
