# GradeBookAI — Безопасность и соответствие 152-ФЗ (аудит и усиление защиты)

Пройден аудит репозитория на баги, мёртвый код и соответствие 152-ФЗ. Главное —
убраны два бэкдора, усилено хранение ключей и добавлены аудит и анти-брутфорс.

## Убраны бэкдоры (критично)
- Удалён захардкоженный мастер-пароль администратора (`_get_default_pw`) вместе с
  целиком мёртвым классом `SecureStorage` в security.py. Раньше любой с .exe мог
  расшифровать перенесённые ПДн — обфускация не защищала.
- Удалён дефолтный пароль `DEFAULT_ADMIN_PASSWORD` ("vsgutu_admin_online"), который
  молча принимался при первом входе. Теперь пароль администратора задаётся вручную
  при первом запуске на главном ПК (диалог в форме входа), а на остальных ПК он
  приходит из общей базы PostgreSQL — клиентам ничего настраивать не нужно.
- Добавлена смена пароля администратора в панели (раздел «База данных»).

## Шифрование и ключи
- `cryptography` теперь ОБЯЗАТЕЛЬНА. Слабый самописный XOR-фолбэк удалён —
  при отсутствии пакета приложение честно останавливается с понятным окном
  (раньше молча «шифровало» мусором).
- Ключ шифрования данных (`data.key`) и пароль PostgreSQL (`pg_config.json`)
  больше не лежат открытым текстом: защищены Windows DPAPI и привязаны к учётной
  записи Windows. Старые открытые ключи/пароли читаются и перешифровываются.

## Аудит и защита от перебора (приказ ФСТЭК №21)
- Новый `audit.py`: журнал событий безопасности (входы успех/неудача, создание и
  смена пароля администратора, экспорт ПДн) в `%LOCALAPPDATA%\GradeBookAI\audit.log`.
- Анти-брутфорс: после 5 неверных попыток логин блокируется на 5 минут; состояние
  на диске, поэтому перезапуск программы блокировку не сбрасывает.

## Локализация данных (152-ФЗ ст. 18 ч. 5)
- Боевая база с ПДн должна быть на территории РФ (сервер колледжа в ЛВС или
  российское облако). Предупреждения добавлены в db_config.py и requirements.txt.
  Зарубежный хостинг (Railway и т.п.) для боевых данных не подходит.

## Чистка мёртвого кода
- Удалены: недостижимая `AdminLoginPage` и «секретная кнопка» входа, DEBUG-принты
  в main_window, неиспользуемый метод `DBManager.sync_to_pg`, дублирующая таблица
  `pc_keys`, неиспользуемый импорт `secure_store`, устаревшие GitHub-комментарии.

# GradeBookAI — Release 2.4: GigaChat, надёжность данных, фиксы методики

## 1. Подключение ИИ-провайдера в админке (вкладка «API Ключ»)
Под карточкой OpenRouter добавлена карточка «🐯 ИИ-помощник Вектор»:
выбор провайдера озвучки — Офлайн / GigaChat / локальная ollama. Для GigaChat —
поле ключа (скрытое, с «показать»), выбор SCOPE (PERS для физлица первым в списке,
B2B для юрлица) и кнопка «Проверить ключ» с понятными подсказками об ошибках
(неверный SCOPE, не установлен пакет gigachat). Ключ хранится в config, который
шифруется на диске; в исходники не попадает.

Почему Вектор раньше не отвечал через GigaChat: (1) ключ негде было ввести;
(2) левые панели Вектора стартовали с пустым конфигом (get_provider({})) и всегда
откатывались в офлайн; (3) scope по умолчанию был B2B вместо PERS. Всё исправлено:
обе панели читают реальный config; scope выбирается в админке.

## 2. Конфликты синхронизации вместо тихой перезаписи (core.py)
У оценок появились updated_at + device (имя ПК). Синхронизация в PostgreSQL стала
детерминированной (newest-wins по времени). При настоящем конфликте (разные значения,
время неотличимо) расхождение пишется в sync_conflicts и НЕ затирает работу
преподавателя. В журнале — кнопка «⚠ Конфликты (N)» и окно выбора верного значения
(conflict_dialog.py).

## 3. Авто-бэкапы локальной базы (core.py, main.py)
DBManager.backup() копирует базу в …/GradeBookAI/backups/ с меткой времени, хранит
последние 30. Срабатывает перед загрузкой из PG, при выходе из программы и по кнопке
«🗄 Бэкап». Есть restore() и list_backups().

## 4. SQLite только на локальном диске (core.py)
База теперь всегда в локальной user-папке (%LOCALAPPDATA% / ~/.local/share/GradeBookAI),
никогда на сетевой шаре. Добавлены детект сетевого пути с предупреждением и
PRAGMA WAL + busy_timeout против блокировок и порчи.

## 5. Валидация дат (ui_date.py)
Свободный ввод «дд.мм.гггг» заменён диалогом-календарём (QDateEdit). Кривую дату
(31.02, «завтра», пустую) ввести физически нельзя. Все вводы дат в журнале препода
переведены на него. parse_date/normalize_date проверяют реальный календарь.

## 6. Единая методика среднего балла (grading.py)
Формула вынесена в один модуль — его зовут и core.calculate_average, и Вектор
(расхождение теперь невозможно). Вес пропуска «Н», учитывать ли пропуск и включать ли
экзамены — настраивается (config), дефолты сохраняют прежнее поведение, методика
документирована. При учёте экзаменов берётся ПОСЛЕДНЯЯ попытка (пересдача), а не
первая заваленная — устранён риск «средний по заваленной попытке».

# GradeBookAI — Release 2.3: команды без ИИ, спрайтовый маскот, фикс пересдач

## 1. Меню быстрых команд + ответы без ИИ (vector/faq.py — новый модуль)
- Под чатом Вектора появились КНОПКИ-КОМАНДЫ (свои для студента/препода/админа):
  нажатие = готовый вопрос = мгновенный ответ из SQL, БЕЗ всякой LLM.
- Фаззи-сопоставление: нормализация текста (регистр, ё→е, пунктуация) + словарь
  основ-синонимов с весами. «У кого долги», «кто завалил экзамен», «у кого хвосты»,
  «кому нужна пересдача» → один и тот же интент и один и тот же ответ.
- Если вопрос НЕ из пула (порог по весам) → интент «unknown» → вопрос уходит живой
  LLM (gigachat/ollama, с обезличиванием фамилий); в чистом офлайне — честная
  дружелюбная подсказка, что Вектор умеет.
- Новые заготовленные интенты: привет / спасибо / помощь.

## 2. Дружелюбные офлайн-ответы (vector/llm.py, faq.friendly_wrap)
Даже без LLM ответ теперь трёхчастный: тёплое вступление → точные факты из SQL
(не изменяются) → подсказка следующего шага, с тоном под роль и под ситуацию
(хорошие новости / плохие новости).

## 3. Спрайтовый маскот (vector/widget.py переписан, vector_assets/ — новая папка)
Машина состояний на 4 PNG: 1_idle (статика), 2_thinking (обдумывание),
3_speaking (открыт рот), 4_away (курсор не над чатом). Логика:
- отправка вопроса → thinking; ответ пришёл → ещё 1 c thinking;
- затем speaking 5–7 c (длительность по длине ответа) → idle;
- курсор ушёл с панели → 2 c idle → away; вернулся → idle;
- перенос панели вправо (⇄) → спрайт зеркалится; свернуть → скрывается с панелью.
Поддержка покадровой анимации: папка vector_assets/<state>/ с PNG-кадрами.
Пока арта нет — работают сгенерированные заглушки (см. vector_assets/README.md
с ТЗ для художника). Без PNG — эмодзи-фолбэк, ничего не падает.

## 4. ФИКС: пересдача назначалась всем (teacher_dashboard.py, dashboards.py, core.py)
Дата пересдачи хранится на экзамене, поэтому колонка «Пересдача» была редактируемой
у ВСЕХ студентов. Теперь ячейка пересдачи активна только у того, кто завалил
предыдущую попытку (2 / Н / «Не зачтено», включая «3 (Не зачтено)»). Сдавшим —
серый прочерк «—» без редактирования: в таблице преподавателя, в журнале студента
и в экспорте Excel. Уже проставленные оценки пересдач не прячутся.

  сетевых запросов в обычном случае.
- **Сетевые сбои** — `URLError` (нет сети/таймаут) больше не валит запись с
  неинформативной ошибкой.
- `delete_file` — чистит обе структуры кэша, обрабатывает статусы по коду.

Публичный API модуля не изменён — остальной код править не нужно.

# Итерация 3 — PostgreSQL вместо GitHub, вход по логину/паролю, хеширование

## GitHub удалён полностью
Файл `github_storage.py` удалён. Вместо него — `data_store.py`: то же
key-value-хранилище (students/teachers/groups/config/journals), но на
**PostgreSQL + SQLite**, без обращений в интернет.
- Рабочее чтение/запись — локальный SQLite (мгновенно, не блокирует интерфейс).
- При настроенном PostgreSQL запись дублируется в PG асинхронно (PGSyncer),
  при старте данные подтягиваются из PG в SQLite. Все ПК колледжа — одна база.
- **Побочный эффект:** админ-панель больше не виснет на старте (раньше она
  синхронно лезла в GitHub). Проверено: создаётся за ~0.2 с.

## Хеширование паролей
Пароли НЕ хранятся в открытом виде. `security.py`: `hash_password` /
`verify_password` (PBKDF2-HMAC-SHA256, 200 000 итераций, случайная соль).
`data_store` хеширует пароль прозрачно при записи (поле `password` → `password_hash`).

## Вход по логину и паролю
- Единая форма входа: **Логин + Пароль + «Войти»** (вместо вкладок Ученик/Учитель
  и ввода ФИО). Роль (студент/учитель/админ) определяется автоматически по логину.
- `data_store.authenticate(login, password)` — единая точка проверки.

# Итерация 4 — Брендинг ВСГУТУ и шифрование данных

## Надпись «Технологический колледж ВСГУТУ»
Добавлена в трёх местах: на экране входа (бирюзой под подзаголовком),
в шапке приложения (под «GRADEBOOK») и в заголовке окна.

## Шифрование данных на диске
Все значения в хранилище (kv_store: роутер студентов с ФИО, учётки
преподавателей, журналы, API-ключ) теперь **шифруются** при записи
(Fernet/AES, см. security.py: encrypt_value / decrypt_value).
- Ключ шифрования хранится в ОТДЕЛЬНОМ файле `data.key` (в APPDATA\GradeBookAI),
  НЕ в базе. Поэтому украденный файл базы без ключа нечитаем.
- Приложение расшифровывает прозрачно — остальной код не изменился.
- Старые незашифрованные записи читаются как есть и шифруются при следующей записи.

Проверено: в файле базы ФИО и API-ключ лежат как `enc:...` (нечитаемо),
приложение и вход работают.

⚠️ **Важно для нескольких ПК:** файл `data.key` должен быть ОДИНАКОВЫМ на всех
ПК колледжа (иначе ПК не расшифрует общие данные из PostgreSQL). Скопируйте его
на все машины вместе с программой.

## Честно о границах защиты (важно!)
Зашифрован реестр студентов/учителей, журналы и API-ключ (kv_store).
**НЕ зашифрованы пока** рабочие таблицы журнала (`students`, `grades`) в локальном
SQLite-кэше — там ФИО и оценки лежат открытым текстом, потому что по ним идут
связи (join) и их шифрование требует детерминированной схемы (отдельная задача).
Для боевого режима эти данные защищаются на уровне сервера PostgreSQL:
ограничение доступа к БД + шифрование диска сервера (см. дорожную карту, 152-ФЗ).
