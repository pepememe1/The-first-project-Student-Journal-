# ━━ ЧТО ВКЛЮЧИТСЯ САМО ПОСЛЕ УСТАНОВКИ ━━
# Ничего переключать не придётся: продукт спрашивает «умеет ли ЭТА машина» в рантайме, а
# не читает тумблер.
#   • перевод      — translate_service.status(): пакет есть + модели есть → работает;
#   • распознавание — stt_service: пакет есть → /web/vector/stt отвечает, кнопка голоса

#   • озвучка      — tts_service: torch есть → синтез работает.
# Модели Whisper и Silero докачиваются САМИ при первом обращении. Руками ставятся только
# модели Argos — это и делает tools/provision_ai_host.py.

# ━━ ПОЧЕМУ ЭТОТ НАБОР НЕЛЬЗЯ СТАВИТЬ НА НЫНЕШНИЙ VPS ━━
# Не «не рекомендуется», а измерено (tools/measure_argos_memory.py, 02.09.2026):
#   import argostranslate            252 МБ (тянет stanza и torch)
#   первая модель ru→en             +263 МБ
#   прирост сверх уже живого torch   343 МБ на ОДНУ пару
# На боевом VPS свободно 342 МБ при 960 МБ всего. Не влезает даже ОДНОСТОРОННИЙ перевод.
# Плюс одно ядро: любой счёт модели останавливает журнал всему колледжу.
#
# ⚠️ ПРИВЯЗКИ К КОНКРЕТНОЙ МАШИНЕ ЗДЕСЬ НЕТ И НЕ ДОЛЖНО БЫТЬ. Ориентир — КЛАСС: Ryzen 7/9
# или Xeon, 32/64 ГБ ОЗУ, видеокарта на 12/16 ГБ. Сама машина ещё не выбрана, и файл,
# знающий её характеристики, устареет раньше, чем её купят. Решение «потянет или нет»
# принимает `server/app/hostcaps.py` по порогу, а не по модели железа.
#
# ⚠️ ЧЕСТНО О КАЧЕСТВЕ ПЕРЕВОДА. Argos на предметной лексике плох, и это проверено:
# «две пары по математике» → «two math couples», через пивот в китайский →
# «两对数学夫妇» (две супружеские пары математиков), а en→zh местами выдаёт мусор из
# субтитров. Установка НЕ делает перевод функцией, которую можно обещать покупателю.
# Прямой пары ru↔zh у Argos нет — идём через английский, потери накапливаются дважды.
