# Тест с другом бесплатно (гайд для чайника, РФ-способы)

Cloudflare в РФ часто не работает — здесь бесплатные способы, которые обычно
работают: проброс порта + бесплатный домен (лучший для РФ) и SSH-туннели
(встроены в Windows, ставить ничего не надо).

---

## Сначала — как это устроено (простыми словами)

- **Сервер** — «общая папка с данными» в интернете. Запустим у тебя на ПК.
- **Программа** (у тебя и у друга) — пустая коробка. Сама данных не хранит, она
  их **скачивает** с сервера и **отправляет** туда. Как Telegram: пока не вошёл и
  нет сети — пусто; вошёл → скачались твои данные.
- **Публичный адрес** — интернет-ссылка на твой сервер, видимая из любой точки
  (`http://что-то:порт` или `https://что-то`). Домашний `192.168.x.x` виден
  только в твоей квартире — другу бесполезен.
- **Почему «пустая прога» друга наполнится:** он входит логином/паролем → прога
  идёт по публичному адресу на ТВОЙ сервер → скачивает данные оттуда.

```
Ты (админ) → заводишь данные → они на СЕРВЕРЕ (твой ПК + публичный адрес)
Друг → запускает прогу → входит → СКАЧИВАЕТ данные с того же сервера
```

---

## Шаг 1. Запусти сервер (у себя). Окно НЕ закрывать.
```
cd server
python run.py
```
Проверка: http://localhost:8000/health → `{"status":"ok"}`.

---

## Шаг 2. Сделай адрес публичным — выбери ОДИН способ

### Способ A (лучший для РФ): проброс порта + бесплатный домен DuckDNS
Данные идут напрямую к тебе, без зарубежных туннелей. Нужен «белый» (публичный) IP.

**Проверь, белый ли у тебя IP:**
1. Зайди на whatismyipaddress.com — запомни IP (например `95.x.x.x`).
2. Зайди в роутер (обычно 192.168.0.1 или 192.168.1.1) → найди «WAN/Интернет» →
   посмотри IP там.
3. Если IP совпадают — у тебя **белый IP**, способ A подойдёт. Если в роутере
   `10.x.x.x` / `100.64.x.x` — это «серый» IP (CGNAT), способ A не сработает →
   бери способ B.

**Настройка:**
1. Бесплатный домен: duckdns.org → войти (Google/GitHub) → создать поддомен,
   напр. `vsgutu.duckdns.org` → там же кнопка прописать твой текущий IP.
2. В роутере: «Проброс портов» (Port Forwarding) → внешний порт `8000` →
   на локальный IP твоего ПК (узнать: `ipconfig` → IPv4) порт `8000`.
3. **Публичный адрес = `http://vsgutu.duckdns.org:8000`**.
4. Проверь с телефона (мобильный интернет, Wi-Fi выкл):
   `http://vsgutu.duckdns.org:8000/health` → `{"status":"ok"}` 🎉

### Способ B (без проброса, без установки): SSH-туннель
Подходит при «сером» IP. SSH уже встроен в Windows 10/11. В ОТДЕЛЬНОМ окне:
```
ssh -R 80:localhost:8000 serveo.net
```
или, если serveo не отвечает:
```
ssh -R 80:localhost:8000 localhost.run
```
Команда напечатает публичный адрес вида `https://что-то.serveo.net` или
`https://что-то.lhr.life`. **Это твой публичный адрес.** Окно не закрывать.

### Способ C: ngrok
Зарегистрироваться на ngrok, поставить, прописать токен, затем:
```
ngrok http 8000
```
Выдаст `https://xxxx.ngrok-free.app` — это публичный адрес (на бесплатном тарифе
меняется при каждом запуске; в проге мы уже добавили обход страницы-предупреждения).

> Любой из способов даёт «публичный адрес». Запомни его — он понадобится дальше.

## Шаг 3. Стань админом и заведи данные
Рядом со своей прогой создай в Блокноте файл `api_config.json`:
```json
{ "api_url": "ТВОЙ_ПУБЛИЧНЫЙ_АДРЕС" }
```
(например `http://vsgutu.duckdns.org:8000` или `https://xxx.serveo.net`)

Запусти прогу → войди логином `admin` → задай пароль (первый запуск). Заведи
студентов и **учётку другу** (например логин `drug`, пароль `drug12345`). Данные
сами уйдут на сервер.

---

## Шаг 4. Отдай другу прогу + адрес
Друг сам ничего не создаёт — всё даёшь ты:
1. Собери `.exe` (как раньше собирал тот, что в `D:\GradeBookAI`, — нужна НОВАЯ
   сборка, со синхронизацией).
2. Рядом с `.exe` положи `api_config.json` с тем же публичным адресом.
   (Или без файла: впиши адрес в `app_settings.py` → `DEFAULT_API_URL` ПЕРЕД
   сборкой — тогда адрес «зашит» в .exe.)
3. Заархивируй в zip, отправь другу (облако/мессенджер).

---

## Шаг 5. Друг запускает
1. Распаковал, запустил `GradeBookAI.exe`.
2. Ввёл логин `drug` и пароль `drug12345`.
3. Прога сходила на твой сервер по публичному адресу и **скачала данные** — друг
   видит то, что ты завёл. ✅

---

## Частые затыки
- **«Откуда друг возьмёт api_config.json?»** Его создаёшь ТЫ (Блокнотом) и кладёшь
  рядом с .exe в zip. Друг ничего не создаёт.
- **«Откуда прога знает адрес?»** Из `api_config.json` рядом с .exe или из зашитого
  `DEFAULT_API_URL`. Больше неоткуда.
- **У друга пусто / не входит.** Проверь: окна сервера и туннеля ОТКРЫТЫ; в
  `api_config.json` друга стоит АКТУАЛЬНЫЙ адрес (у туннелей он меняется при
  перезапуске); проверь адрес с телефона через `/health`.
- **Серый IP.** Способ A не сработает — бери B (SSH) или C (ngrok).
- **Адрес меняется при перезапуске туннеля.** Норма для бесплатных. Обнови адрес
  в `api_config.json`. Постоянный адрес даёт способ A (DuckDNS) или боевой сервер.

---

## ⚠️ Про реальные данные (152-ФЗ)
SSH-туннели и ngrok идут через зарубежные серверы — это **только для теста на
выдуманных данных**. Способ A (DuckDNS + твой белый IP в РФ) держит данные в РФ,
но без HTTPS — тоже для теста. Боевой режим (реальные ПДн) — сервер в РФ с HTTPS,
см. `DEPLOY.md`, раздел 7.
