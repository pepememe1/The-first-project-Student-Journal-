# GradeBookAI — Бэкенд (Фаза 1)

Сервер-посредник между данными и клиентами (десктоп-прога + будущий сайт).
Клиенты НЕ ходят в БД напрямую — только через этот API по HTTPS. Пароль от БД
знает только сервер.

## Зачем так
- **Offline-first сохраняется:** десктоп работает на локальном SQLite без сети, а
  когда видит сервер — синхронизируется через `/sync`. Это киллер-фича (не ложится
  от блокировок/отсутствия интернета).
- **Безопасность:** на клиентах нет пароля БД. Доступ — по JWT, роли admin/teacher/
  student. Пароли только хешами (формат совпадает с десктопом).
- **Один API для проги и сайта.**

## Запуск (разработка, SQLite)
```bash
pip install -r server/requirements.txt
cd server
uvicorn app.main:app --reload --port 8000
```
Документация: http://localhost:8000/docs

## Боевой сервер ВСГУТУ (PostgreSQL)
1. Скопировать `server/.env.example` → `server/.env`, задать:
   - `GRADEBOOK_DB_URL=postgresql://vsgutu_user:ПАРОЛЬ@localhost:5432/vsgutu_grades`
   - `GRADEBOOK_JWT_SECRET=<длинная случайная строка>`
2. Запустить за reverse-proxy (nginx) с HTTPS. БД и сервер — в РФ (152-ФЗ).

## Эндпоинты (Фаза 1)
- `GET  /health` — проверка живости.
- `POST /auth/bootstrap-admin` — создать первого админа (только если его ещё нет).
- `POST /auth/login` — вход, возвращает JWT.
- `GET  /sync/pull?since=<ISO>` — изменения позже метки (дельта-синк).
- `POST /sync/push` — отправить изменения (LWW по updated_at; права по роли).

## Модель синхронизации
Каждая сущность несёт `updated_at` (ISO) и `deleted` (надгробие). Десктоп хранит
метку последней синхронизации, тянет дельту и отправляет накопленные офлайн
изменения. Конфликты оценок десктоп уже разрешает локально; на сервере — LWW.
