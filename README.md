## О проекте

**GradeBookAI** — это десктопное приложение для ведения электронного журнала успеваемости,
разработанное командой **Synapse**. Главная идея — **local-first**: программа мгновенно работает
офлайн на локальной базе SQLite, а при наличии сети асинхронно синхронизирует данные через
**REST API-сервер ВСГУТУ** (FastAPI), чтобы все ПК колледжа видели одну базу. Прямого подключения
к серверной БД с клиента нет — обмен идёт только через API.

Ключевая фишка — встроенный ИИ-помощник **«Вектор»**, который отвечает на вопросы по журналу,
**никогда не выдумывая цифры**: все данные он берёт реальными SQL-запросами к базе, а облачная
LLM лишь переформулирует уже готовые факты.

> ⚠️ Приложение обрабатывает персональные данные студентов. См. раздел
> [Безопасность и 152-ФЗ](#-безопасность-и-152-фз).

## ✨ Ключевые возможности

- **Три роли с разграничением доступа** — Администратор, Преподаватель, Студент. Каждый видит
  только то, что ему положено.
- **Local-first архитектура** — чтение и запись идут в локальный SQLite (без задержек UI),
  фоновый поток синхронизирует данные через REST API-сервер. Полная работоспособность офлайн.
- **ИИ-маскот «Вектор»** — тигр-ассистент с настоящим артом в полный рост (два независимых
  слоя: речь в чате + эмоция по успеваемости), работает офлайн (локальный шаблонизатор /
  Ollama) или через GigaChat. Анти-галлюцинации by design. **И на десктопе, и на сайте**:
  LLM-озвучка, разграничение по ролям, боковой док-компаньон, настройки ИИ (провайдер/ключ
  GigaChat) синхронизируются десктоп↔веб.
- **Голосовой ввод «Вектор слушает»** — распознавание речи (OpenAI Whisper через
  faster-whisper, аудио не уходит третьим лицам; GPU/CPU). Студент/админ — голосом задают
  любые вопросы (всё, что можно текстом). Преподаватель — ещё и ставит оценки/пропуски, в т.ч.
  **пачкой**: «Иванову пять, Петрову четыре», «всей группе пять», «первым десяти по списку
  четыре», а также **создаёт занятие** («создай сегодня лекцию по теме …»). Команды
  разбираются **детерминированно** (без галлюцинаций LLM), массовая запись показывается
  **списком на подтверждение**, при неоднозначности — переспрос. Кнопка «?» — примеры команд
  для каждой роли. Корректно работает с бурятскими ФИО (Самбуева, Гындынова, Баянжаргал…).
- **Локальный ИИ (Ollama) с выбором модели под видеокарту** — в настройках Вектора пикер
  моделей по объёму VRAM (3B для 6 ГБ … 14B для 12 ГБ). Ничего не уходит наружу.
- **Веб-редакция (Vue 3 SPA)** на https://esstu-gradebook.ru — тот же сервер и БД, что у
  десктопа. Устанавливается как **PWA** (иконка на телефоне, работа офлайн-оболочки),
  **вход по passkey** (Face ID/отпечаток/ключ доступа), тема-роуминг, расписание, Вектор.
  Цель — 1:1 с десктопом ([web/PARITY-PLAN.md](web/PARITY-PLAN.md)).
- **Расписание и предметы с сайта ВСГУТУ** — клиент сам тянет публичный портал расписания
  (`portal.esstu.ru`), разбирает HTML в модель и кладёт в локальный зашифрованный кэш;
  вкладка «Расписание» открывается уже актуальной (фоновое авто-обновление при старте).
  Один виджет на все роли: студент видит свою группу, преподаватель — свои пары, админ — любую.
  **Список предметов тоже берётся из расписания** (спарсен с сайта) — не «вшит текстом»,
  всегда актуален; при отсутствии кэша — фолбэк на локальный `subjects.json`.
- **Токены и сессии (152-ФЗ)** — вход по JWT с **жёстким сроком ~5 часов** (refresh = access):
  после 5 часов нужен повторный вход, «накопления» сессий нет. **Чёрный список токенов**:
  «Выйти» и админский отзыв мгновенно аннулируют токен. У админа — вкладка **«Сессии и
  доступ»**: видно активные токены и кнопка «Отозвать» (экстренная блокировка / смена ролей).
  Оба токена хранятся **зашифрованно** (DPAPI/Fernet).
- **Барьер подтверждения устройств** — новый ПК сначала запрашивает доступ; администратор
  принимает запрос и диктует 6-значный код. Неодобренное устройство сервер не пускает (`403`).
- **Полевое шифрование** — чувствительные поля шифруются Fernet; ключ данных защищён Windows DPAPI
  (привязка к учётной записи ПК). Пароли — двухэтапный гибридный хеш (PBKDF2-HMAC-SHA512, 200 000
  итераций → PBKDF2-Стрибог512 по Р 50.1.111-2016), никогда не хранятся в открытом виде.
- **Гибкий расчёт среднего балла** — единый источник правды (`grading.py`): учёт пропусков «Н»,
  опциональный учёт экзаменов с пересдачами — всё настраивается вузом.
- **Импорт/экспорт Excel** — выгрузка и загрузка журналов через `.xlsx` (openpyxl).
- **Авто-бэкап** локальной базы при выходе из программы.
- **Фирменный стиль Synapse** — шрифты Syne + DM Sans, бирюзовая палитра ВСГУТУ.

## 🐯 ИИ-помощник «Вектор»

«Вектор» — это не «чат-бот поверх ChatGPT», а аккуратный конвейер, где LLM отвечает только
за стиль, но не за факты:

```
вопрос пользователя
   → intents.classify()      распознаём намерение (локально, без сети)
   → intents.<handler>()     реальный SQL к локальной базе → ФАКТЫ
   → privacy.anonymize()     ФИО → «Студент №N» (перед отправкой в облачную LLM)
   → llm.voice()             LLM только ПЕРЕФОРМУЛИРУЕТ факты
   → privacy.deanonymize()   возвращаем настоящие имена локально
   → VectorResponse          текст + настроение + сами факты
```

- **Провайдеры озвучки.** Офлайн-шаблоны (без сети), **GigaChat** (РФ-серверы) или локальная
  модель **Ollama**. Если LLM недоступна — фразы собирает локальный шаблонизатор, поэтому Вектор
  работает всегда.
- **Приватность.** Перед отправкой в облако ФИО обезличиваются — наружу персональные данные
  не уходят.
- **Знания о вузе** (`vector/knowledge.py`) — выверенные факты о ВСГУТУ отвечаются офлайн,
  без LLM, что исключает галлюцинации.
- **Два слоя арта маскота** — слой *речи* (`emotions/речь/`: говорит / думает / ждёт / молчит —
  по состоянию чата) и слой *эмоций* (`emotions/эмоции/`: «морда + жест», выбор по успеваемости:
  плохие оценки → грусть+подбадривание, долги → предупреждение, хороший балл → радость).
  Нет папок с артом → компактная эмодзи-заглушка 🐯, ничего не падает.
- **Живой экран входа** — анимированный фон (частицы + «соты»), Вектор слева: при наведении
  переходит в «думающую» позу и показывает облачко с подсказками по входу и приложению.
- **Боковая шторка Вектора** — Вектор во весь рост, поверх нижней части фигуры — полупрозрачная
  история чата; быстрые команды прячутся во всплывающее меню (по кнопке, как в мессенджере).

## 🏗️ Архитектура

```
┌──────────────────────────────────────────────────────────────────┐
│                      GradeBookAI (PySide6)                         │
│                                                                    │
│   UI ──► чтение/запись ──► SQLite (локальный, мгновенно)           │
│                              │                                     │
│                              ▼  (фоновый поток sync_runner, HTTPS) │
│                     REST API-сервер ВСГУТУ (FastAPI)               │
│                              ▲                                     │
│                              └──► другие ПК колледжа               │
└──────────────────────────────────────────────────────────────────┘
```

- **SQLite всегда локальный** — никогда не на сетевой шаре (иначе блокировки и порча файла).
- **Общее состояние между ПК — только через REST API-сервер** (см. каталог `server/`).
  Прямого подключения к серверной БД с клиента нет.
- Офлайн-изменения накапливаются локально и досинхронизируются при восстановлении сети
  (last-write-wins по метке времени, конфликты оценок фиксируются явно).
- Данные хранятся в key-value таблице `kv_store` (ключ → JSON): студенты, преподаватели,
  группы, конфиг, журналы.

## 🔐 Безопасность и 152-ФЗ

- **Шифрование БД сервера при хранении (SQLCipher, AES-256)** — весь файл серверной БД
  зашифрован на диске (ПДн at rest): при краже файла данные не прочитать без ключа. Ключ —
  64 hex в `server/.env` (chmod 600, не в git). Включается прозрачно (схема id не меняется);
  без ключа/драйвера — обычный SQLite (dev/Windows). Миграция — `server/encrypt_db.py`.
- Поля чувствительных данных на КЛИЕНТЕ шифруются (**Fernet**); ключ данных защищён
  **Windows DPAPI** (привязка к учётке ПК). На сервере телефон в заявках — ГОСТ-шифр
  («Кузнечик»/Стрибог, `server/app/gost.py`). Без `cryptography` шифрование намеренно
  отключается с понятной ошибкой — **слабых самописных фолбэков для ПДн нет**.
- Пароли хранятся только в виде **двухэтапного гибридного хеша** `hybrid_sha512_gost512`:
  PBKDF2-HMAC-SHA512 (200 000 итераций) → PBKDF2-Стрибог512 (ГОСТ Р 50.1.111-2016).
  ГОСТ-бэкенд авто: **OpenSSL GOST-engine (C-скорость) — включён на боевом сервере** →
  gostcrypto на dev. Индивидуальная соль, сравнение в постоянное время; формат
  самоописываемый (старые хеши проверяются без сброса паролей).
- **Вход по passkey (WebAuthn) — Face ID / отпечаток / ключ доступа** без пароля: приватный
  ключ в защищённом чипе устройства, биометрия — часть протокола. Веб: `/auth/webauthn/*`.
- **Персистентный журнал аудита** (ФСТЭК №21): входы/выходы, изменения оценок и ПДн,
  регистрации — в отдельной append-only таблице БД (`server/app/audit.py`), переживает
  рестарт; админ смотрит через `/web/admin/audit`.
- **HTTP security-заголовки** (Caddy): HSTS, X-Frame-Options DENY, X-Content-Type-Options
  nosniff, Content-Security-Policy, Referrer-Policy.
- **Управление сессиями:** access-JWT сгорает через 5 ч (`exp` — абсолютная метка сервера,
  офлайн-время учитывается — обойти отключением сети нельзя); refresh-токен тихо обновляет
  access; сервер ведёт **чёрный список** выданных токенов (`AuthSession`) — logout и админский
  отзыв мгновенно закрывают доступ. Оба токена на клиенте — в зашифрованном локальном хранилище.
- **Барьер подтверждения устройств** — неодобренный ПК получает `403` на `/auth/*`, `/sync/*`,
  `/me/*`, `/admin/*` (опознание по заголовку `X-Device-Id`).
- Журнал аудита (`audit.py`) фиксирует входы и значимые события; есть анти-брутфорс на клиенте
  и на сервере (`server/app/throttle.py`, блокировка после серии неудачных попыток) — приказ
  ФСТЭК России №21.
- Серверный SQLite работает в режиме **WAL + `busy_timeout`** — конкурентные входы/записи не
  падают с `database is locked` (для реального масштаба — PostgreSQL).
- ИИ-конвейер обезличивает ФИО перед отправкой в облачную LLM (GigaChat); офлайн/Ollama наружу
  не отправляют ничего. GigaChat выбран как LLM в РФ-юрисдикции (российские серверы).

> **Важно перед публикацией / продакшеном:**
> 1. Пароль администратора задаётся при первом запуске (захардкоженного дефолта нет).
> 2. **Адрес API-сервера должен быть `https://`** — ПДн (ФИО, оценки) идут по сети, канал
>    обязан быть защищён TLS. Сам сервер размещается на территории РФ (152-ФЗ, ст. 18 ч. 5).
> 3. Репозиторий рекомендуется держать **приватным**, пока не пройдён аудит 152-ФЗ.
> 4. Рантайм-файлы (`secure_data.enc`, `data.key`, `*.db`, `server/.env`) исключены из git
>    через `.gitignore` — не коммитьте их. Адрес сервера хранится в локальной БД самой
>    программы, отдельного `api_config.json` больше нет.

## 🚀 Установка и запуск

> Требуется **Python 3.10+**.

```bash
# 1. Клонировать репозиторий (десктоп — в корне монорепо)
git clone https://github.com/<ваш-логин>/GradeBookAI.git
cd GradeBookAI

# 2. Создать виртуальное окружение
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt

# (опционально) живая озвучка Вектора через GigaChat:
pip install gigachat

# 4. Запустить
python main.py
```

При первом запуске программа работает на локальном SQLite. Если адрес сервера не задан,
при старте появится окно **«введите API сервера для синхронизации»** (его можно закрыть и
работать офлайн). Адрес также задаётся со страницы входа (кнопка **«⚙ Сервер»**) или в
админке во вкладке **«Сервер»**; для разработки — переменная окружения `GRADEBOOK_API_URL`.
Сам сервер — в каталоге `server/` (FastAPI).

### Сервер на ПК администратора и переход на PostgreSQL

Для небольшого колледжа один ПК может быть и рабочим местом администратора, и сервером
синхронизации. В админ-панели → вкладка **«Сервер и сайт»**:

1. **Состояние** сверху показывает по реальной доступности адреса, работает ли сервер и
   сайт прямо сейчас (ловит и сервер на VPS) — а не только локальный процесс.
2. **Адрес сайта и онлайн-базы** — единый адрес (по умолчанию вшит `https://esstu-gradebook.ru`),
   редактируемый. Один адрес и для сайта, и для синхронизации.
3. **Разместить сервер на этом ПК** — выбор движка **SQLite 3 / PostgreSQL**, одна кнопка
   **«Запустить сайт и онлайн-базу»** поднимает FastAPI/uvicorn **внутри самой программы**
   (внешний Python не нужен) + HTTPS (Caddy) по домену из адреса. Полученный адрес сам
   записывается в программу; «Остановить» гасит сервер+сайт.
4. Клиентам раздать `.exe` (или дать ссылку на сайт); адрес сервера в сборке уже вшит.
   Подключаются они **к API**, а не к БД напрямую.

> Клиенты к PostgreSQL не подключаются — обмен идёт только через API-сервер. Полный гайд
> по боевому развёртыванию (сервер в РФ, HTTPS, systemd, бэкапы) — в
> [server/DEPLOY.md](server/DEPLOY.md).

## 📁 Структура проекта

> Код разложен по папкам `ui/ sync/ data/ schedule/ vector/`, но импорты остались
> **плоскими** (`from core import ...`) — это работает за счёт `_bootstrap.py`, который
> кладёт эти папки в `sys.path`. Path-чувствительные модули (main, main_window, grading,
> subjects, server_control, fonts) оставлены в корне.

```
gradebook/
├── main.py                 # точка входа (--run-server поднимает сервер из .exe)
├── _bootstrap.py           # кладёт ui/ sync/ data/ в sys.path (плоские импорты)
├── main_window.py          # главное окно, маршрутизация по ролям, авто-обновление расписания
├── app_paths.py            # единый источник путей (портативность .exe)
├── grading.py              # единый расчёт среднего балла
├── subjects.py             # предметы и занятия (+ subjects.json)
├── server_control.py       # хостинг сервера из админки (detached-процессы, serveo)
├── data/                   # данные и безопасность
│   ├── core.py             #   DBManager, локальный SQLite (WAL), бэкапы, экспорт
│   ├── data_store.py       #   key-value хранилище (kv_store), кэш сессии
│   ├── app_settings.py     #   адрес API-сервера, device_id, сохранённая сессия
│   ├── security.py         #   гибридный хеш пароля + Fernet + DPAPI
│   └── audit.py            #   журнал событий и анти-брутфорс (152-ФЗ)
├── sync/                   # синхронизация
│   ├── sync_client.py      #   HTTP-клиент к REST API-серверу (X-Device-Id)
│   ├── sync_engine.py      #   слияние изменений (LWW), надгробия, конфликты
│   └── sync_runner.py      #   фоновый поток синхронизации
├── ui/                     # интерфейс
│   ├── auth_pages.py       #   экраны входа («⚙ Сервер», подтверждение устройства)
```
