# План устранения техдолга GradeBookAI

> Составлен после сеанс-ревью (июль 2026). Мелкие правки уже сделаны (см. раздел
> «Сделано»). Ниже — крупные проблемы, которые нельзя чинить «на бегу»: каждая
> требует отдельного плана и тестов. Порядок — по соотношению «риск для продукта /
> цена». Правило проекта: **перед крупной правкой — короткий план, потом код.**

## Сделано (этот сеанс, хирургически)

- **Тулинг Python:** `ruff` + `black` + `mypy` (конфиг в `pyproject.toml`,
  `requirements-dev.txt`). Линтер — на высокосигнальный набор (реальные баги, не стиль).
- **Тулинг Web:** `eslint` (flat config) + `prettier` (`web/eslint.config.js`,
  `.prettierrc.json`, npm-скрипты `lint`/`format`).
- **CI:** добавлены джобы `lint-python` (ruff) и `lint-web` (eslint) в `.github/workflows/ci.yml`.
- **Логгер:** `log.py` — файловый логгер с ротацией (в .exe без консоли диагностика
  больше не теряется). Проведён в критичный синк-путь (`sync_engine`, `sync_runner`).
- **Баги, найденные линтером и починенные:**
  - мёртвый дубль роутов `teacher_create/update/delete_lesson` в `server/app/routers/web.py`
    (ruff F811) — FastAPI брал первый, дубль был миной при рефакторинге → удалён;
  - неиспользуемые переменные/импорты (F401/F841) по всему коду — вычищены;
  - коллизия имён бэкапов при разрешении часов Windows ~15 мс (два бэкапа в одно
    окно затирали друг друга — потеря копии) → уникальный суффикс в `core.backup()`.

## Крупные проблемы (нужен отдельный заход на каждую)

### 1. Полный дамп БД на десктоп при синке → дельта-выборки по роли `[безопасность, ВЫСОКИЙ]`

**Проблема.** `/sync/pull` отдаёт ВСЕ строки всех таблиц SYNC_MODELS, включая
`password_hash` всех пользователей и `config` (ключи ИИ). Барьер устройств спасает,
но радиус поражения одного скомпрометированного одобренного ПК — вся база (152-ФЗ).

**✅ Стадия 1 — СДЕЛАНО и задеплоено** (`sync._scope_pull_for_role`):
- не-админ получает СВОЙ хеш (для офлайн-входа), чужие хеши — вырезаны;
- секретные ключи `config` (токен GigaChat; паттерн credential/token/secret/api_key/
  password) не уходят не-админам; админ получает всё (нужно для правки юзеров, сохранения
  старого хеша при смене без пароля);
- токен GigaChat остался ТОЛЬКО на сервере → десктоп озвучивает факты через
  `POST /vector/voice` (`ServerProvider` в `vector/llm.py`, `SyncClient.voice`); движок
  обезличивает факты и для server-провайдера (данные уходят в сеть).
- Тесты: `server/tests/test_sync.py` (pull по ролям + voice), `tests/test_vector_provider.py`.

**⏳ Стадия 2 — row-scope ПДн (следующий заход):** не слать студенту чужих студентов
(только своя группа/сам), преподавателю — только его группы/предметы. Больший 152-ФЗ-
выигрыш, но выше риск сломать десктоп-UI (нужна ручная проверка каждой роли).
**Тесты:** pull под teacher/student не содержит чужих ПДн.

### 2. Две несовместимые модели данных (kv-JSON десктоп ↔ ORM сервер) `[архитектура, ВЫСОКИЙ]`

**Проблема.** `sync_engine` — целый слой-переводчик `students_to_users`,
`teachers_to_users` и т.п. Каждая новая сущность = ручная проводка `collect/apply` в обе
стороны (это делали для `term_grades`). Источник багов и налог на любую фичу.

**Подход (поэтапно, без «большого взрыва»).**
1. Завести на десктопе нормальные таблицы `users/groups` (как уже есть `lessons/grades/
   term_grades`) вместо JSON в `kv_store`.
2. Перевести `data_store` на чтение/запись этих таблиц, сохранив публичный API
   (`get_students` и пр.) — UI не трогаем.
3. Выкинуть переводчики из `sync_engine` — синк станет как для `lessons` (прямой upsert).

**✅ Стадия 1 — СДЕЛАНО (пилот `groups`):** группы переехали из kv-блоба в ТАБЛИЦУ
`groups` (серверная форма, id=`grp:{name}`). `data_store.get_groups/set_groups` сохранили
прежнюю форму (UI не тронут), внутри — таблица + одноразовая миграция kv→таблица.
Переводчик `groups_to_rows` УДАЛЁН: синк ходит прямым upsert'ом (`_collect_groups` /
`_merge_groups`, как `lessons`). Тесты: `tests/test_groups_table.py` (round-trip, надгробия,
миграция, «не будит синк»). Формат на проводе не изменился — сервер не трогали.

**✅ Стадия 2 — СДЕЛАНО (`users` студенты+преподаватели, blob-шифрование).** Мина безопасности
(kv шифруется, а таблицы — нет) обойдена: таблица `users` хранит `id/role/updated_at/deleted`
открытыми служебными колонками (для прямого синка), а сам payload — ЗАШИФРОВАННЫМ `blob`
(Fernet+DPAPI, серверная форма JSON). Хеши паролей и ПДн на диске защищены как прежде; на
провод/офлайн-вход уходит расшифрованный хеш. Переводчики `students_to_users`/`teachers_to_users`
и `_merge_by_key` УДАЛЕНЫ — синк ходит прямым upsert'ом (`_collect_users`/`_merge_users`, как
`lessons`). `data_store` конвертирует server↔desktop-форму на границе UI (get/set_students,
get/set_teachers) — UI не тронут. Админ по-прежнему в `config` (в таблицу `users` не пишется).
Миграция kv→таблица НЕДЕСТРУКТИВНА (старые kv-ключи оставлены бэкапом для отката).
Бонус: отчество студентов и `curated_groups` кураторов теперь синхронизируются (раньше терялись).
**Тесты:** `tests/test_users_table.py` (шифрование at-rest, round-trip+офлайн-вход, миграция,
надгробия, админ в config, «не будит синк»). Клиент 189 зелёный. Формат на проводе не изменился.

**⚠️ Затестировать на десктопе:** миграция реальной БД (студенты/преподаватели → таблица) —
перед раскаткой прогнать сам десктоп (вход, журнал, админка) и сделать бэкап БД. Юнит-тесты
покрывают логику, но GUI-путь стоит проверить руками.

### 3. Дублирование бизнес-логики Python ↔ JS `[корректность, СРЕДНИЙ-ВЫСОКИЙ]`

**Проблема.** `isFailed`, `needsRetake`, логика пересдач, выбор эмоций (`mascot.js` —
«порт `emotes.pick`»), расчёт статусов — переписаны на JS. Каждый порт = точка
расхождения; при правке Python одна из версий отстаёт молча.

**Подход.** Правило «сервер — единственный источник правды для расчётов»:
1. Всё, что можно, считать на сервере и отдавать готовым (`/web/*` уже так для среднего).
2. Веб/десктоп — тонкие клиенты: не пересчитывают, а показывают.
3. Что нельзя вынести (мгновенная UI-реакция) — покрыть парными тестами-контрактами
   (один и тот же вход → один и тот же выход на Python и JS).

**✅ Стадия 1 — СДЕЛАНО (fail-логика оценок):** правило «завалена ли оценка» больше НЕ
дублируется инлайном — единый `grading.is_failed` (Python; на него перешли десктоп
`teacher_dashboard._is_failed` и сервер `webdata.debts`) и `web/src/utils/grades.js`
(JS-порт; `TeacherJournal.vue` импортирует его). Общий golden-контракт
`docs/contracts/grade-cases.json` проверяется ПАРНО: `tests/test_grade_contract.py`
(pytest) и `web/tests/grades.contract.test.mjs` (node:test, в CI) — молчаливое
расхождение реализаций теперь невозможно.

**✅ Стадия 2 — СДЕЛАНО (логика пересдач):** `needs_retake` + формат ключа попытки —
единый `grading.attempt_key`/`grading.needs_retake` (десктоп) и `grades.js`
(`attemptKey`/`needsRetake`); +9 кейсов в `grade-cases.json`, парные тесты pytest+node.

**✅ Стадия 3 — СДЕЛАНО (эмоции маскота):** выбор эмоции `vector/emotes.py::pick`
(русский кортеж морда+жест) ↔ `web/src/config/mascot.js::pickEmote` (строка 'face-gesture')
закреплён контрактом `docs/contracts/mascot-cases.json` (мост русский↔английский —
`face_map`/`gesture_map`; кейсы пиннят и приоритет веток). Парные тесты:
`tests/test_mascot_contract.py` + `web/tests/mascot.contract.test.mjs` (оба в CI).

**⏳ Дальше:** постепенно выносить сами РАСЧЁТЫ на сервер (тонкие клиенты) — там, где
это не бьёт по мгновенной UI-реакции; остальное держать под контрактами (как сейчас).

**Риск.** Рост числа запросов к серверу; кэширование. **Тесты:** контрактные (golden-файлы).

### 4. `_bootstrap.py` (sys.path-хак) → нормальный пакет `[поддерживаемость, СРЕДНИЙ]`

**Проблема.** Плоские импорты через подмену `sys.path`. IDE/mypy/сторонние инструменты
спотыкаются; `pytest` работает только со своим `pythonpath` в `pytest.ini`.

**✅ Боль ИНСТРУМЕНТОВ — закрыта (без перестройки):** IDE (Pylance) резолвит плоские
импорты через существующий `pyrightconfig.json` (`extraPaths`), а mypy — через добавленный
`mypy_path = "ui:sync:data"` в `pyproject.toml`. `pytest` уже работал (`pythonpath` в
`pytest.ini`). Т.е. «IDE/mypy спотыкаются» — решено, `_bootstrap` на рантайме безвреден.

**⏳ Полный перенос в пакет `gradebook/` — ОТЛОЖЕН (делать ПОСЛЕ демо-встречи, с ручной
GUI-проверкой).** Подход: `ui/ sync/ data/` + десктоп-модули → пакет `gradebook/` (кодмод
импортов), `grading.py` ОСТАЁТСЯ в корне (шарится с сервером), точка входа `main.py` →
тонкий лаунчер / `python -m gradebook`, спеки PyInstaller обновить, пересобрать exe.
**⚠️ МИНА (не ловится тестами):** `vector/emotes.py` и `fonts.py` вычисляют корень проекта
как `dirname(папки модуля)` — при переносе `vector/`/`fonts.py` в пакет корень сдвинется и
АРТ маскота + шрифты перестанут грузиться (видно только в GUI). Перед переносом: либо
чинить эти `__file__`-пути (через `app_paths`), либо оставить `vector/`/`schedule/`/`fonts.py`
в корне как чистые пакеты/модули. **Тесты:** весь набор + smoke-ЗАПУСК exe с проверкой арта.

**Риск.** Массовая правка импортов + пересборка .exe + рантайм-мины ресурсных путей.

### 5. `alert()/confirm()/prompt()` в вебе → модалки/тосты `[UX/продукт, СРЕДНИЙ]`

**Проблема.** `setGrade`, `setExamGrade`, назначение пересдачи используют браузерные
диалоги — дёшево выглядит для коммерческого продукта, блокирует поток.

**Подход.** Один переиспользуемый `useConfirm()`/`useToast()` composable + компонент
модалки (уже есть `components/ui/*`). Заменить точечно в `TeacherJournal.vue` и остальных.

**✅ СДЕЛАНО.** `useToast` + `ToastHost.vue` (неблокирующие уведомления вместо `alert`),
`useConfirm` + `ConfirmDialog.vue` (промис-модалки вместо `confirm`/`prompt`, с danger-
вариантом, фокусом в поле и Esc). Хосты смонтированы один раз в `App.vue`. Заменены ВСЕ
~30 браузерных диалогов: `TeacherJournal.vue` (12) + `AdminGroups/Registrations/Teachers/
Subjects/Students` (18). Браузерных `alert/confirm/prompt` в `web/src` больше нет. eslint
чисто, сборка ок. **Веб надо задеплоить** (dist → VPS), чтобы увидеть на боевом сайте.

### 6. Постепенные типы (mypy) + расширение линтера `[качество, НИЗКИЙ, фоново]`

**✅ Итерация СДЕЛАНА.** Ruff расширен правилом **`B` (bugbear)** с игнором `B008`
(`Depends(...)`/`Body(...)` в дефолтах — штатный паттерн FastAPI). Починены 9 реальных
находок: `B905` (zip без strict), `B904` ×3 (raise без `from` в server-роутерах),
`B007` ×5 (неиспользуемые loop-переменные → `_`). Mypy сфокусирован
(`follow_imports = silent` — ошибки в ещё-нетипизированных транзитивных модулях не топят
проверку) и расширен: `grading.py`, `data/terms.py`, `data/exports.py`, `log.py`,
`app_paths.py` — зелёный.
**⏳ Дальше:** добавлять `files` в mypy по модулю за раз (с аннотациями); при готовности —
`SIM` в ruff (`I`/сорт импортов НЕ трогать — порядок важен для `_bootstrap`).

### 7. Свод `except: print(...)` → логгер (механически) `[наблюдаемость, НИЗКИЙ]`

**✅ СДЕЛАНО.** 101 диагностический `print(f"[...]")` в 21 модуле (`ui/ vector/ schedule/
data/` + `main_window/main/server_control/fonts`) переведён на файловый логгер:
`print(f"[tag] …")` → `log.get("<модуль>").warning(f"[tag] …")` (сообщения 1:1, меняется
только маршрут — теперь пишется в `<данные>/logs/gradebook.log`). Консольные `diag_*` и
стартовые info-print без скобок оставлены. Синк был на логгере ранее.
**⏳ Дальше (по желанию):** `except: pass` в важных местах → `_log.exception(...)` — точечно,
с комментарием там, где пустой `except` действительно безвреден.

## Прочее (быстрые, вне кода фич)

- **Смена root-пароля VPS** и отключение парольного SSH (`PasswordAuthentication no`) —
  пароль засветился в переписке. Ходить только по ключу `gb_vps_ed25519`.
- **`npm audit`** в вебе: 8 уязвимостей в dev-зависимостях — разобрать `npm audit fix`.
- **Postgres по умолчанию** для прод-сервера (сейчас SQLite/SQLCipher; Postgres для масштаба).
- **Пересборка .exe с `excludes`** для STT/ML-пакетов (faster-whisper/ctranslate2/av) —
  вернёт вес ~221 МБ → ~123 МБ (в .exe голос всё равно не работает, см. CLAUDE.md §5.2).
