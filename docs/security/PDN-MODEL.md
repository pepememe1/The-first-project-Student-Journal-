## 1. Кто оператор

**Оператор — ВСГУТУ.** У вуза есть утверждённая Политика обработки персональных данных
(приказ от 06.04.2026 № 915од), студенты в ней заявлены категорией субъектов. По п. 2
ст. 3 152-ФЗ оператор — тот, кто определяет цели и состав обработки; цели (учёт
успеваемости, аттестация) — уставная деятельность вуза. Разработчик передаёт право
использования программы (ст. 1235, 1286 ГК) и обработку не ведёт.

Две нормы политики вуза — жёсткие ограничения для продукта:

| пункт политики | что это значит для нас |
|---|---|
| 5.2.4.1 «не поручает обработку другому лицу» | сервер живёт на железе ВСГУТУ; доступ разработчика к боевой базе — только по договору (ч. 3 ст. 6 152-ФЗ) |
| 5.6.1 «трансграничная передача не осуществляется» | перевод — офлайн (Argos), Google удалён целиком; внешние сервисы — только без ПДн, см. §5 |

`web/public/privacy.html` — **приложение** к политике вуза, описывающее одну
информационную систему, а не вторая политика.

⚠️ **Пока сервер на арендованном VPS, пункт 5.2.4.1 не выполняется.** Закрывается
переездом (`deploy/install.sh`, [развёртывание на железе ВСГУТУ](./DEPLOY-VSGUTU-SECURE.md)), а не
документом.

## 2. Субъекты и состав данных

| субъект | что хранится | откуда |
|---|---|---|
| студент | ФИО, группа, логин, почта и телефон (по желанию), оценки, посещаемость (Н/Б/О), итоговые, день рождения **без года**, аватар и «о себе», сообщения и вложения | колледж, сам студент |
| преподаватель | ФИО, логин, предметы и группы, кураторство, почта и телефон | колледж |
| родитель | ФИО, логин, связь с ребёнком (действует только после согласия студента) | колледж |
| администратор | ФИО, логин | колледж |
| все | журнал безопасности: логин, действие, время, **отпечаток** адреса (не сам адрес) | сервер |

Пароль не хранится нигде — только хеш (`hybrid_sha512_gost512`). Телефоны в заявках,
контакты для защиты входа и выданные колледжем пароли зашифрованы отдельно «Кузнечиком»
(`server/app/gost.py`) поверх шифрования всей базы.

## 3. Где лежат данные

| место | что | защита |
|---|---|---|
| сервер, база | всё из §2 | SQLCipher (AES-256) целиком, ключ `GRADEBOOK_DB_KEY`; отдельные поля — «Кузнечик» (`GRADEBOOK_DATA_KEY`) |
| сервер, резервные копии | снимок базы раз в сутки, 14 штук | зашифрованы тем же ключом; ⚠️ лежат на той же машине |
| сервер, вложения | файлы сообщений и материалов курсов | хранилище выбирает машина (`storage.mode()`); на текущем VPS выключено |
| программа ПК | личная копия базы на каждый логин + база синхронизации | SQLCipher целиком, ключ устройства под DPAPI; смена аккаунта стирает чужие копии |
| программа ПК, снимок при закрытии | личная копия (`backups/personal`) | только зашифрованный, `VACUUM INTO` |
| программа ПК, %TEMP% | снимок **публичного** расписания портала (в нём ФИО преподавателей) | Fernet под ключом устройства, подпись; подделка молча пропускается (`desktop/temp_cache.py`) |
| браузер | сессия, черновики (ключ с логином), очередь неотправленных оценок, офлайн-кэш ответов `/web/*` | черновики и кэш стираются при выходе; мессенджер не кэшируется вовсе |
| телефон | то же, что браузер, плюс надёжное зеркало очереди в хранилище приложения | песочница Android; см. ⚠️ ниже |
| пуш-уведомления | нейтральный текст и номер события | текст собирает сервер, не отправитель (`rustore_push.push_text`) |

⚠️ **Очередь неотправленных оценок переживает выход из аккаунта — намеренно.** Она
привязана к логину автора; стирать её при выходе значит потерять всё, что преподаватель
выставил без сети. Цена: на общем телефоне до появления сети лежат фамилии и оценки,
которые видит только этот логин. Надёжное зеркало (`@capacitor/preferences`) повторяет
ту же политику: пустеет вместе с очередью.

## 4. Кто что видит

Права проверяются на сервере в каждой ручке (`server/app/deps.py`, `routers/web/*`):
спрятанная кнопка защитой не считается.

| роль | читает | пишет |
|---|---|---|
| студент | свои оценки, посещаемость, итоговые; расписание и курсы своей группы; каталог людей мессенджера | свой профиль, сообщения, согласие родителю |
| преподаватель | свои предметы × свои группы (`SubjectHours.teacher_id`); свои курсы | оценки и посещаемость по своим предметам; закрытый итоговой семестр — только после снятия итоговой |
| куратор | то же + отчёты по курируемым группам | отчёты для родителей в канале группы |
| родитель | журнал своего ребёнка — **только после согласия студента**; повторная привязка после отзыва снова требует согласия | ничего в журнале |
| администратор | справочники, пользователи, журнал безопасности, модерация | справочники, пользователи, расписание; наружу в модерации подписан `moderator:N` |

Полный снимок базы через `/sync/*` веб-клиенту закрыт (`routers/sync.py::_deny_web`).
Секреты из строки `config` не уходят в `/sync/pull` никому, включая администратора;
администратор получает только свой хеш пароля.

## 5. Что уходит наружу

Подробно — [SUBPROCESSORS.md](SUBPROCESSORS.md). Коротко: GigaChat получает только
обезличенные ответы (интенты с фамилиями в модель не идут вовсе — флаг `no_voice`,
сторож `server/tests/test_vector_never_voices_names.py`); Klipy — только поисковый
запрос; Open-Meteo — только город; RuStore — нейтральный текст пуша. Каждый внешний
сервис выключается настройкой без правки кода.

## 6. Честные границы

- административный доступ держится на **одном пароле** (второй фактор у `admin`
  выключен решением от 05.09.2026) плюс анти-брутфорс, аудит и приманки;
- резервные копии на той же машине: получивший root получает и копии;
- журнал безопасности можно пересчитать целиком, владея базой, — доказательство даёт
  только контрольная точка, сохранённая вне машины (`server/verify_audit.py --checkpoint`);
- на общем телефоне неотправленные оценки лежат до появления сети (§3);
- антивирусной проверки вложений нет: защита — белый список типов и размер.
