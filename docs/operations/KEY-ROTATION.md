# Ключи GradeBookAI: где лежат, как менять, что сломается

> Сверено с кодом 27.09.2026 (Release 4.1). Для администратора сервера и того, кто
> выпускает обновления. Смена ключа — плановая операция: без спешки, в окно простоя,
> с резервной копией ДО. Любой пункт с пометкой «механизма нет» — не менять, пока не
> появится инструмент: результат — нечитаемые данные.

## 1. Сводная таблица

| ключ | где лежит | что защищает | потеря | утечка | механизм смены |
|---|---|---|---|---|---|
| `GRADEBOOK_DB_KEY` | `.env` или учётные данные systemd | вся база с ПДн (SQLCipher) | **база и все копии нечитаемы навсегда** | база читается целиком | `server/rotate_db_key.py` (§2) |
| `GRADEBOOK_JWT_SECRET` | там же | подпись токенов входа | все выходят из аккаунтов | можно выписать себе любую роль | смена + перезапуск (§3) |
| `GRADEBOOK_DATA_KEY` | там же | телефоны, контакты входа, выданные пароли («Кузнечик») | эти поля нечитаемы | поля читаются | **механизма нет** (§4) |
| `GRADEBOOK_INDEX_KEY` | там же | слепой индекс для поиска по шифрованным полям | поиск по ним перестаёт находить | перебор значений по индексу | **механизма нет** (§4) |
| `GRADEBOOK_SMTP_PASS`, `GRADEBOOK_KLIPY_API_KEY`, `GRADEBOOK_RUSTORE_SERVICE_TOKEN`, `GRADEBOOK_S3_KEY`/`_SECRET` | там же | почта, GIF, пуши, хранилище вложений | функция выключается | чужие расходы и рассылки | у поставщика + перезапуск (§5) |
| ключ GigaChat | строка `config` в базе, «Настройки ИИ» | озвучка Вектора | Вектор отвечает шаблонами | чужие расходы | у Сбера + сохранить в «Настройках ИИ» (§5) |
| подпись обновлений программы (Ed25519) | закрытый: `~/.gradebook/release_signing_key.hex` на машине выпуска; открытый: `desktop_update.UPDATE_PUBLIC_KEYS` | подлинность .exe | **обновления программы больше не выпустить** | можно раздать подделку | список ключей (§6) |
| подпись обновлений телефона (ECDSA P-256) | закрытый: `~/.gradebook/ota_signing_key.pem`; открытый: `web/src/config/ota-public-keys.json` | подлинность бандла по воздуху | обновления по воздуху не выпустить; только новым APK | можно раздать подделку | список ключей (§6) |
| подпись APK | `web/android/release.keystore` + `keystore.properties`, вне git | подлинность приложения в RuStore | **новые версии не выпустить вообще** | подделка приложения | не меняется; только бережётся (§7) |
| ключ устройства программы | `data.key` рядом с базой, под DPAPI | локальные копии на ПК | копии нечитаемы, скачаются заново | нужен ещё и вход в Windows того же человека | переустановка каталога данных (§8) |
| SSH-ключ к серверу | у администратора | вход на машину | вход только по паролю или консолью | полный доступ к машине | `authorized_keys` (§9) |

🔑 Все закрытые ключи — с резервной копией **вне рабочей машины**. Потеря ключа базы или
ключей подписи не лечится ничем.

## 2. Ключ базы (`GRADEBOOK_DB_KEY`)

```bash
cd server
../venv/bin/python rotate_db_key.py --check        # на КОПИИ, живое не трогает
systemctl stop gradebook
../venv/bin/python rotate_db_key.py --apply        # сам сделает копию до подмены
systemctl start gradebook
curl -sS -o /dev/null -w '%{http_code}\n' https://<домен>/health
```

`--check` перешифровывает копию одноразовым ключом и проверяет, что новый ключ базу
открывает, а старый — нет (в выводе `hmac check failed` — это доказательство, а не сбой).
`--apply` отказывает при работающей службе.

⚠️ **Резервные копии, снятые ДО смены, остаются на СТАРОМ ключе.** Их 14 и живут они две
недели. Старый ключ хранить (запечатанным, вне машины), пока последняя такая копия не
уйдёт по сроку, — иначе восстановиться в эти две недели будет нечем.

## 3. Подпись токенов (`GRADEBOOK_JWT_SECRET`)

Сменить значение и перезапустить службу. Следствия: каждый выходит из аккаунта и входит
заново; программа на ПК продолжает работать офлайн (у локального сервера свой ключ), но
синхронизация ждёт повторного входа. Это и нужно при утечке — выпущенные токены
перестают действовать сразу.

## 4. Ключи полей (`GRADEBOOK_DATA_KEY`, `GRADEBOOK_INDEX_KEY`)

**Механизма перешифровки нет.** Смена значения делает нечитаемыми телефоны в заявках,
контакты защиты входа и выданные пароли; смена ключа индекса ломает поиск по ним. При
подозрении на утечку одного этого ключа при нетронутом ключе базы поля защищены
шифрованием базы целиком — это не авария, а повод завести инструмент.

## 5. Ключи внешних сервисов

Выпустить новый ключ у поставщика, заменить значение, перезапустить службу, отозвать
старый. Ключ GigaChat живёт в базе: сохранить новый в «Настройках ИИ» администратора —
строка обновится, и в копии программ она приедет **без** секрета (секреты `config` не
уходят в `/sync/pull` никому). Старый ключ отозвать у Сбера.

## 6. Ключи подписи обновлений — по списку

И у программы, и у телефона открытых ключей **список**, а не один: с единственным ключом
его смена отрезала бы от обновлений всех, кто ещё не обновился.

1. Создать новую пару, закрытую половину — в `~/.gradebook/` и в резервную копию.
2. Дописать открытую половину в список (`desktop_update.UPDATE_PUBLIC_KEYS` или
   `web/src/config/ota-public-keys.json`), старую **оставить**.
3. Выпустить обновление, подписанное **старым** ключом: оно привезёт людям новый список.
4. Дальше подписывать новым. Старый убрать из списка, когда парк обновился.

Ворота выкладки проверяют подпись тем же кодом, что и клиент
(`tools/sign_release.py --verify`, `tools/sign_ota.py` в `web/deploy/release-ota.ps1`).
Пустой список ключей — отказ, а не «проверять нечем, пропускаем».

## 7. Ключ подписи APK

Не меняется: новая подпись — это для RuStore и для телефонов другое приложение. Две
копии `release.keystore` и `keystore.properties` на разных носителях вне рабочей машины.

## 8. Ключ устройства программы

Свой у каждого ПК, под DPAPI Windows-пользователя. Инструмента смены нет и он не нужен:
при подозрении — отправить несохранённое (значок синхронизации пуст), закрыть программу,
удалить каталог данных; при следующем входе ключ и копии создадутся заново. ⚠️ Правки,
не ушедшие на сервер, при этом теряются.

## 9. SSH

Новый ключ — в `~/.ssh/authorized_keys` на сервере, проверить вход новым, удалить
старый. При передаче сопровождения (см. [SUPPORT-HANDOVER.md](SUPPORT-HANDOVER.md)) —
обязательно: ключи прежней команды убираются в тот же день.
