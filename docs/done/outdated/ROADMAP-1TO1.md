# GradeBookAI Web → 1:1 с десктопом. План доработки

> Цель: веб-версия воспроизводит **функции, экраны, дизайн и безопасность** десктопа
> (минус Speech-to-text — согласовано). Веб пишет напрямую на сервер (онлайн), десктоп
> подхватывает изменения через `pull` — двусторонняя правда через одни и те же
> серверные таблицы (`SYNC_MODELS`). Метку времени для LWW ставит **сервер**.
>
> Статус на 2026-07-03. Ветка сайта — `Alpha-1`, сервер — `pre-release-2.7`.

---

## 1. Как считаем «1:1»

Паритет по пяти осям: **функции · экраны · расчёты · дизайн · безопасность**. Ниже —
матрица «десктоп ↔ сайт» и разрывы, затем фазы работ в порядке приоритета.

## 2. Что уже есть на сайте (факт из кода)

**18 страниц:** admin (Dashboard, Teachers, Students, Groups, Subjects, Requests,
Sessions, Monitor, Theme), student (Dashboard, Journal, Stats), teacher (Journal,
Students, Stats), общие (Login, Vector, Profile, Schedule).

**Серверные эндпоинты для веба** (`server/app/routers/web.py`): всё, кроме одного, —
**только чтение** (`GET`): `student/{overview,journal,stats}`,
`teacher/{overview,journal,students,stats}`, `admin/{overview,teachers,students,
groups,subjects}`, `schedule`, `schedule/groups`. Единственная запись — `POST
/web/vector/ask`.

**Инфраструктура готова:** JWT-авторизация (5ч, жёсткая — см. фикс токена),
device-барьер для персонала снят (открытый веб-доступ, согласовано), HTTPS (Caddy +
Let's Encrypt), SPA раздаётся сервером, темы через `me/prefs`, мониторинг
(`admin/{online,events,sessions}`), расписание студента (пункт 4 — готово).

## 4. Фазы (в порядке приоритета)

### Phase B — Запись/CRUD. Это ядро журнала — БЕЗ неё сайт не журнал 🔴

**Сервер (`web.py` + новый `webwrite.py`), роль-скоуп + валидация, запись в
`SYNC_MODELS`, метку ставит сервер:**
- `POST /web/teacher/grade` — выставить/изменить оценку. Через **единую формулу
  расчёта** (порт `grading.py`), логика пересдач, запись конфликтов как в `/sync/push`.
  Проверка: препод пишет только по своим предметам/группам.
- `POST /web/teacher/lesson` — пара/посещаемость.
- `POST|PUT|DELETE /web/admin/students` — CRUD студента. Пароль — **тот же гибридный
  хеш** (`server/app/security.py`), НЕ хранить открытым. Поле «группа» — выбор из
  синкнутых групп (**пункт 3 на сайте**) + создать свою.
- `.../groups`, `.../subjects` — CRUD, зеркало десктопа.

**Фронт (Vue):**
- `TeacherJournal.vue` → редактируемая сетка оценок (клетка = ввод, автосохранение,
  индикатор синка).
- `AdminStudents.vue` → «+ Добавить»/правка/удаление, группа из списка (пункт 3).
- `AdminGroups.vue` / `AdminSubjects.vue` → CRUD + кнопка «🏫 Из расписания» (как в
  десктопе).

**Инвариант:** запись идёт в те же таблицы, десктоп получит через `pull`. Не дублировать
формулу оценок — вынести общий модуль/портировать `grading.py` на сервер.

### Phase C — Вектор (ИИ-маскот) 1:1 🟡
- Проверить/довести `POST /web/vector/ask`: реальный конвейер
  `intents → SQL-факты → privacy.anonymize → LLM voice → deanonymize` (никаких
  выдуманных цифр — инвариант §5). Провайдеры: офлайн-шаблоны → GigaChat → Ollama.
- Маскот: 30 спрайтов, реактивные эмоции по `(mood, intent)` как в десктопе (часть есть).
- Проактивные карточки `insights` на дашбордах студента/препода.

### Phase D — Расписание препода (пункт 2) + UX 🟡
- Teacher-режим в `/web/schedule`: если ФИО препода совпало со спарсенным
  (`teacher_index`) → сразу его пары; не совпало → две **невыбранные** кнопки
  «Расписание преподавателя» / «Расписание группы».
- Графики успеваемости (чарты) — паритет с десктопом.
- Реалтайм-обновление списков (мониторинг, оценки) — polling/SSE.

### Phase E — Дизайн 1:1 🟡
- Шрифты **Syne + DM Sans** (self-hosted, инлайн). Палитры/токены = `ui/styles.py` /
  `ui/themes.py`. Карточки с тенями, sidebar/header — пиксельная сверка.
- Тёмная/светлая тема + роуминг (`me/prefs`) = десктоп.
- Пройти экран-в-экран со скринами десктопа (то, на что ты жаловался «не похоже»).

### Phase F — Безопасность / 152-ФЗ + CI/CD 🟡
- Аудит-лог веб-действий (ввод/правка оценок, CRUD ПДн — значимые события, §6).
- CORS сузить на прод-домен (`GRADEBOOK_ALLOWED_ORIGINS=https://esstu-gradebook.ru`).
- `deploy/update-vps.ps1` → GitHub Actions: push в `Alpha-1` → сборка → авто-деплой.

## 5. Порядок и почему

1. **Phase B** — без ввода оценок это витрина, а не журнал. Начинать здесь.
2. **Phase C** — Вектор как ключевая фишка продукта.
3. **Phase D** — расписание препода (пункт 2) + чарты.
4. **Phase E** — дизайн под эталон.
5. **Phase F** — безопасность записи + автопубликация.

## 6. Инварианты — НЕ ломать (перенос из десктопа)

- Роли проверять на КАЖДОМ write-эндпоинте (студент ≠ права препода/админа).
- Метку времени LWW ставит сервер; `push` идемпотентен; конфликты оценок не затирать.
- Расчёт среднего — только через единую формулу (не дублировать веса/пересдачи).
- Пароли — только гибридный хеш, никогда открытым; секреты вне Git.
- Device-барьер персонала на вебе снят осознанно (креды + анти-брутфорс + HTTPS +
  role-scoped `/web/*`). Десктоп — барьер строгий.
