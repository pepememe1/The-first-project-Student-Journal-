# GradeBookAI — Web Edition

Веб-версия электронного журнала успеваемости **Технологического колледжа ВСГУТУ**.
Повторяет функционал и фирменный дизайн десктоп-приложения (PySide6), но:

- работает в браузере на телефоне, планшете, ноутбуке и ПК (адаптивный интерфейс);
- **лёгкая и быстрая** (сборка ≈ 73 КБ gzip JS) — открывается даже на слабом интернете;
- **без Speech-to-text** (распознавание речи в вебе не поддерживается — по требованию);
- сидит на **том же REST API**, что и десктоп, и на **том же адресе**, что и сайт.

> Десктоп-версия (первоисточник функционала и дизайна) — приватный репозиторий
> `The-first-project-Student-Journal-`. Веб-версия НЕ дублирует бизнес-логику: расчёт
> оценок и «Вектор» остаются на сервере (единый источник правды).

## Архитектура «один адрес»

```
                 ┌──────────────── https://gradebookai.ru ───────────────┐
   Браузер ─────▶│  Caddy / Nginx                                         │
   (телефон/ПК)  │   ├─ /                → статика SPA (dist/, этот репо)  │
                 │   └─ /auth /me /web … → FastAPI (uvicorn :8000)         │
   Десктоп ─────▶│                         (тот же адрес, те же логины)    │
                 └────────────────────────────────────────────────────────┘
```

- **Адрес сайта = адрес сервера.** Прокси отдаёт SPA в корне домена и проксирует
  известные API-префиксы в FastAPI. Десктоп указывает тот же адрес — он бьёт в
  `/auth`, `/sync`, которые тоже проксируются.
- **CORS не нужен:** SPA и API — один origin. Быстро и безопасно.
- **152-ФЗ:** TLS терминируется на вашем сервере (Caddy/Let's Encrypt), а не у
  иностранного посредника. Конфиги — в [`deploy/`](deploy/).

## Модель доступа (важно)

Десктопный **барьер подтверждения устройства** для веба разведён по ролям:

- **Студенты** входят в браузере открыто (логин/пароль + серверный анти-брутфорс + HTTPS).
- **Преподаватели и администраторы** проходят веб-подтверждение устройства: браузер
  запрашивает доступ (`/connect/request`), администратор одобряет и диктует 6-значный
  код, пользователь вводит его (`/connect/verify`). Тот же поток, что в десктопе.

Аккаунты по-прежнему заводит только администратор (в десктоп-проге), они
синхронизируются на сервер хешами паролей — веб их не создаёт.

## Запуск (разработка)

```bash
npm install
npm run dev          # http://localhost:5173, API проксируется на localhost:8000
```
Параллельно поднимите API десктопа:
```bash
cd ../The-first-project-Student-Journal-/server
uvicorn app.main:app --reload --port 8000
```

Сборка и предпросмотр прод-бандла:
```bash
npm run build        # → dist/
npm run preview
```

Настройки — в `.env` (см. `.env.example`). Для обычной сборки (сайт и API на одном
адресе) менять ничего не нужно.

## Что уже работает vs что на бэкенде

**Готово во фронте:** дизайн-система и все 16 палитр + тёмная тема (страница
«Оформление» — полностью рабочая), вход по JWT с тихим refresh, ролевая навигация и
guard'ы, веб-подтверждение устройства для персонала, чат-каркас «Вектора», мониторинг
админа (на существующих `/admin/online`, `/admin/events`).

**Нужно реализовать на сервере (`server/` десктоп-репо):**

1. **Role-scoped READ-эндпоинты `/web/*`** — сервер отдаёт только то, что роль вправе
   видеть, уже в готовом для UI виде (расчёт — через `grading.py`, единый источник):
   `/web/student/overview|journal|stats`, `/web/teacher/overview|journal|students|stats`,
   `/web/admin/overview|teachers|students|groups|subjects`, `/web/schedule`.
   Причина: `/sync/pull` отдаёт ВСЕ строки всех таблиц (включая `password_hash` и чужие
   оценки) — в браузер это выгружать нельзя.
2. **Разведение барьера устройства по ролям** — студент открыто, персонал по
   подтверждению (см. «Модель доступа»).
3. **Серверный «Вектор»** — анти-галлюцинационный конвейер (intents → SQL →
   анонимизация → LLM) на эндпоинте `/web/vector/ask`.

Контракт этих эндпоинтов зафиксирован в `src/api/endpoints.js`.
