# Соответствие УЗ-3: карта требований → что закрывает прога, что — ВСГУТУ

> **Статус:** техническая карта силами разработки, **не аттестация**. Финальное
> заключение и аттестацию ИСПДн делает лицензиат ФСТЭК. Здесь — честное «что уже
> закрыто кодом, что лежит на инфраструктуре/ОРД ВСГУТУ, где пробелы».
> Классификация дана заказчиком; ссылки — ПП РФ № 1119, Приказ ФСТЭК № 21,
> Приказ ФСБ № 378.

## Классификация (вход)

| Критерий | Значение |
|---|---|
| Категория ПДн | Иные (ФИО, оценки, посещаемость, группы, ID) + общедоступные |
| Спец./биометрия | НЕ обрабатываются |
| Кол-во субъектов | > 100 000 (студенты + сотрудники + архив выпускников) |
| Тип актуальных угроз | 3-й тип (уязвимости прикладного ПО; ОС/АО — нейтрализованы) |
| **Итоговый уровень** | **УЗ-3** |

## Разделение зон ответственности

- **Прога/код (мы)** — меры внутри приложения и его архитектуры.
- **Инфраструктура ВСГУТУ** — сеть, серверы, ОС, физика, сертифицированные СЗИ.
- **ОРД ВСГУТУ** — приказы, регламенты, согласия, назначение ответственных.

> Большинство мер УЗ-3 — инфраструктурные/организационные и лежат на ВСГУТУ. Наша
> задача — закрыть прикладные меры и не мешать остальным.

## Карта мер УЗ-3 → статус

| Мера (УЗ-3 / Приказ № 21) | Зона | Статус в проекте |
|---|---|---|
| **Разграничение доступа по ролям** (студент/преподаватель/админ) | Прога | ✅ Сделано: 3 роли, студент видит своё, преподаватель — свои предметы (в т.ч. построчная авторизация push на сервере), админ — всё |
| **Аутентификация, надёжный хеш пароля** | Прога | ✅ Двухэтапный хеш PBKDF2-SHA512 + Стрибог512 (ГОСТ); анти-брутфорс на клиенте и сервере (429) |
| **Парольная политика** (длина, спецсимволы, смена раз в 90 дней) | Прога + ОРД | ⚠️ Частично: минимум 8 символов есть; обязательные спецсимволы и принудительная смена раз в 90 дней — **НЕ реализованы** (кандидат на доработку) |
| **Двухфакторная аутентификация** | Прога | ⚠️ Нет (для УЗ-3 2FA рекомендована, не строго обязательна) — кандидат на будущее |
| **Регистрация событий: вход/выход** | Прога | ✅ `audit.py` (клиент), `events.py` + журнал входов (сервер) |
| **Регистрация: изменение оценок (кто/когда)** | Прога | ⚠️ Частично: у оценки есть `device`/`updated_at` и конфликты пишутся в `sync_conflicts`; **полного пер-оценочного аудита «кто изменил с X на Y» нет** — кандидат на доработку |
| **Регистрация: выгрузка списков/оценок (экспорт)** | Прога | ⚠️ Экспорт в xlsx **не логируется** — кандидат на доработку |
| **Защищённый канал (HTTPS, при требовании — ГОСТ-TLS)** | Прога-ready + Инфра | ◻ Готовность есть (TLS-проверка всегда вкл., свой CA `GRADEBOOK_CA_BUNDLE`); **ГОСТ-TLS терминирует ViPNet/прокси** — инфра (см. `server/DEPLOY.md`) |
| **Изоляция БД от интернета (DMZ, SQL не наружу)** | Инфра + архитектура | ✅ Архитектурно: клиент к серверной БД НЕ подключается, только через API; БД остаётся за сервером. Сам DMZ/firewall — ВСГУТУ |
| **Резервное копирование** | Прога + Инфра | ✅ Авто-бэкап локальной базы по расписанию; **изолированное хранилище бэкапов** (другой носитель, права) — инфра ВСГУТУ |
| **Сертифицированный МЭ на периметре** | Инфра | ВСГУТУ |
| **СЗИ от НСД на серверах** (Dallas Lock / Secret Net / Astra SE) | Инфра | ВСГУТУ |
| **Антивирус (централизованный)** | Инфра | ВСГУТУ |
| **Закрытие уязвимостей ОС/СУБД, лишних портов** | Инфра + частично прога | Сервер слушает один порт; остальное — ВСГУТУ |
| **Контроль физического доступа к серверам** | Инфра | ВСГУТУ |
| **Сертифицированные СКЗИ** (канал/при необходимости — данные) | Инфра (закупка) + интеграция | ViPNet/КриптоПро; хеш-этап ГОСТ уже встроен (см. ниже) |

## Прикладные пробелы под УЗ-3 (кандидаты на доработку в коде)

Закрываются кодом, на стороне приложения (с тебя — приоритеты):
1. **Парольная политика:** обязательные спецсимволы + принудительная смена раз в 90 дней
   (сейчас только длина ≥ 8).
2. **Пер-оценочный аудит:** журнал «кто, когда, с какого значения на какое» по каждой
   правке оценки (сейчас — метка `device`/`updated_at` + конфликты, но не полный трейл).
3. **Логирование экспорта:** фиксировать выгрузку списков/оценок в xlsx.
4. (Опционально) **2FA** для входа.

> Это НЕ блокеры запуска, но для аттестации по УЗ-3 их стоит закрыть. Скажешь —
> сделаю отдельной аккуратной задачей (затрагивает аудит и вход — сначала план).

## Крипто-меры (где мы уже есть)

- **Хеш пароля:** двухэтапный `hybrid_sha512_gost512` — PBKDF2-SHA512 (стойкость) →
  PBKDF2-Стрибог512 по Р 50.1.111-2016 (ГОСТ). На бою ГОСТ-этап — через сертифицированное
  СКЗИ (OpenSSL gost-engine / ViPNet). Диагностика бэкенда — `python diag_gost.py`.
- **Канал:** ГОСТ-TLS через ViPNet — отдельный раздел `server/DEPLOY.md`.
- **Подробный план крипты и 152-ФЗ:** `docs/STRIBOG_152FZ_PLAN.md`.
