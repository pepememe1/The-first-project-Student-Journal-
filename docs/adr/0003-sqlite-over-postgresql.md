# ADR-0003: Одна SQLite/SQLCipher база

## Status

Accepted

## Date

2026-09-12

## Контекст

Продукт реально работает с одной SQLite базой, включая боевой SQLCipher-путь. Вторая
непроверенная ветка PostgreSQL создавала ложную уверенность и удваивала миграционные и
тестовые обязанности.

## Решение

SQLite остаётся единственной базой продукта. На защищённой машине файл открывается через
SQLCipher с ключом из настроек секретов; WAL и `busy_timeout` смягчают конкуренцию, но
ограничение одного writer считается действующим.

## Альтернативы

- Вернуть PostgreSQL заранее: это добавит непроверенный путь без доказанной потребности.
- Использовать Redis для сообщений и состояния: он не заменяет долговечную SQL-историю.

## Последствия

Нельзя включать несколько worker-процессов только числом в командной строке. Переход на
другую СУБД возможен отдельным проектом после измерения lock contention и требований к
распределённой записи.

## Rollback

Откат изменения приложения выполняется на совместимый SQLite/SQLCipher путь. Возврат
PostgreSQL требует нового ADR, схемы, миграций и полного набора паритетных тестов.
