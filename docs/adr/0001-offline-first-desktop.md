# ADR-0001: Offline-first для десктопа

## Status

Accepted

## Date

2026-09-12

## Контекст

Преподаватель должен продолжать работать с журналом при временном отсутствии сети.
Синхронизация и мессенджер имеют разную цену ошибки: потеря локальной оценки хуже
задержки, а переписка не должна незаметно становиться второй локальной базой.

## Решение

Операция журнала сначала записывается в локальную SQLite/SQLCipher базу, а затем
отправляется фоновым синхронизатором. Сервер остаётся источником серверной метки времени
и разрешения конфликтов. Состояние мессенджера в offline-first слой не включается.

## Альтернативы

- Писать сначала на сервер: сеть становится обязательной для выставления оценки.
- Синхронизировать весь мессенджер: появится второй набор конфликтов, прав и ПДн в
  локальном кэше.

## Последствия

Локальная запись должна быть идемпотентной и иметь очередь изменений. Синк обязан
сохранять надгробия и конфликты, а новые таблицы синка требуют отдельной миграции и
регрессии.

## Rollback

Откатить конкретное изменение синка до предыдущего локального контракта; не удалять
локальные данные и не включать серверную запись в обход очереди.
