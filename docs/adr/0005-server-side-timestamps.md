# ADR-0005: Серверные метки времени

## Status

Accepted

## Date

2026-09-12

## Контекст

Часы устройств расходятся, а оценки, синхронизация, сообщения и аудит используют время
для порядка, идемпотентности и отображения истории. Клиентская метка может быть старой,
будущей или намеренно подменённой.

## Решение

Сервер ставит UTC-метки для записей и разрешения конфликтов. Клиент может показывать
локализованное время устройства, но не определяет порядок серверных изменений.

## Альтернативы

- Доверять времени клиента: разные часы меняют порядок и могут откатывать свежие данные.
- Использовать только монотонный счётчик процесса: он не переносится между процессами и
  не объясняет порядок после рестарта.

## Последствия

Push остаётся идемпотентным, а pull использует включающую границу `updated_at >= since`.
Архивный импорт обязан получить новую серверную метку, иначе восстановление проиграет
локальным данным как устаревшее.

## Rollback

Откатить только вызывающий экран/транспорт, сохранив серверный контракт меток времени.
