# ADR-0007: Ограниченные метрики HTTP-запросов

## Status

Accepted

## Date

2026-09-12

## Контекст

План оптимизации требует измерять latency и ошибки до обсуждения Go, multi-worker или
новой базы. Постоянный лог запросов здесь не подходит: URL и тела могут содержать ПДн,
а боевой сервер работает одним процессом.

## Решение

Приложение собирает в памяти процесса ограниченную статистику по шаблону маршрута и
методу: счётчики, группы HTTP-статусов, байты ответа и p50/p95/p99 по последним 256
наблюдениям. Ответ получает серверный случайный `X-Request-ID`, который не является
идентификатором пользователя. Ручка `/web/admin/server/metrics` показывает снимок только
администратору.

## Граница измерения

Время включает ASGI-обработку и передачу тела, но не включает Caddy/TLS и не является
нагрузочным тестом. Запрос, формирующий снимок, может появиться в статистике только после
завершения. Данные не включают URL-параметры, тела, имена, IP, токены или тексты ошибок.

## Последствия

Снимок помогает выбрать следующий эксперимент и безопасен при рестарте, но не доказывает
межпроцессную ёмкость и не заменяет стенд. Для нескольких workers потребуется отдельный
агрегатор и завершённый shared-state проект.

## Rollback

Удаление middleware и поля `requests` возвращает прежний ответ ручки; основной серверный
контур, роли и база от этой диагностики не зависят.
