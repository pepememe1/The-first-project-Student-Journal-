# ADR-0006: Эксперимент realtime-gateway

## Status

Proposed

## Date

2026-09-12

## Контекст

У мессенджера есть WebSocket и fallback polling, но текущая производительность не
измерена через полный путь Caddy/TLS/Uvicorn/SQLite при конкуренции. Полный rewrite на Go
повторил бы роли, ПДн, модерацию и аудит до доказательства узкого места.

## Решение

Не переносить весь messenger. После baseline и durable events допускается отдельный
gateway только для realtime-доставки, health и graceful drain. Python REST, SQLite,
аутентификация, запись сообщений и модерация остаются источником истины.

## Условия принятия

Нужны одинаковый workload, p50/p95/p99, CPU/RSS, reconnect, duplicate/lost events,
queue lag и проверка паритета сайта, десктопа и Android. Пока этих данных нет, ADR не
разрешает запуск gateway.

## Альтернативы

- Оставить Python realtime: предпочтительно до измерения.
- Полный rewrite: отклонён из-за повторной реализации критических границ.
- Redis Pub/Sub как единственный транспорт: отклонён, потому что потерянное событие
  нельзя воспроизвести.

## Rollback

Canary должен отключаться маршрутом/флагом и возвращать клиентов на Python realtime без
изменения схемы сообщений.
