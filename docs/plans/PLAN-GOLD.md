## 1. Что такое «Золото» и как оно ложится на нас

В играх «золото» (Gold Master) — сборка, которую отдают в печать: после неё код не
меняют, а всё найденное идёт патчем первого дня. До золота игра проходит вехи, и у каждой
есть критерий входа, а не дата в календаре.

| веха в играх | что значит | наш аналог |
|---|---|---|
| Альфа | все функции есть, но сырые | пройдено (3.x) |
| Бета | новых функций нет, ищут и чинят ошибки | **мы здесь**: 4.1 на демо-стенде, боевых данных колледжа нет |
| Заморозка контента | больше не добавляют функции | заморозка функций 1.0 (§3, веха М1) |
| Заморозка кода | меняют только исправления по списку | ветка кандидата (М3) |
| Кандидат в релиз (RC) | сборка, которая может стать финальной | подписанные RC: .exe, APK, OTA, сервер |
| Сертификация платформы | консоль проверяет игру по своим правилам | приёмка ВСГУТУ: 152-ФЗ, ИБ, реестр Минцифры (М4) |
| Золото | финальная сборка ушла в печать | боевая версия на железе ВСГУТУ, домен переключён (М5) |
| Патч первого дня и live ops | исправления после выхода | сопровождение: поток исправлений, OTA, автообновление (М6) |

## 2. Где мы на 27.09.2026

- Три платформы работают на общем сервере: сайт, программа для Windows, приложение
  Android. На демо-бою — 4.1: синк по номеру изменения, очередь досылки, подписанные
  обновления программы и телефона.
- Тесты: клиент 1045, веб 652 — зелёные; сервер — 1971 в полном прогоне 27.09, из них два
  красных оказались настоящими дефектами и починены (плюс новый сторож). Полный серверный
  прогон идёт ~19 минут.
- Документы для приёмки: модель ПДн, регламенты смены ключей, восстановления, передачи
  сопровождения, реестр субобработчиков, регламент инцидентов, SBOM, базовый уровень
  ASVS (`docs/security/`, `docs/operations/`).
- Прода нет: реальных журналов колледжа в системе нет, сервер на арендованном VPS.

## 4. Правила заморозки кода (с М3)

- В ветку кандидата попадают ТОЛЬКО исправления ошибок из списка RC, каждое с тестом,
  который без исправления краснеет.
- Никаких новых колонок и таблиц после RC1, кроме исправления P1. Миграция — отдельное
  решение двоих.
- Никаких обновлений зависимостей, кроме закрытия уязвимости.
- Каждая RC — полные прогоны трёх наборов и живой запуск .exe (окно, минута
  отзывчивости, зашифрованная база).
- Коммит в ветку кандидата — после проверки вторым человеком (или гранью-оппонентом, когда
  она доступна).

## 5. Планка ошибок

| уровень | что это | можно ли выходить на золото |
|---|---|---|
| P1 | потеря или порча данных, чужие данные на экране, обход прав, сервер лежит | нет |
| P2 | функция журнала не работает, нет обходного пути | нет |
| P3 | неудобство или есть обходной путь | да, с записью в известные ограничения |
| P4 | косметика | да |

## 6. Открытые решения (за командой)

1. Второй фактор для администратора: сейчас выключен (решение от 05.09.2026), вход админа
   держится на одном пароле. Для боевой версии — пересмотреть.
2. Удалять ли старый движок синка вместе с его проверками.
3. «Б» и «О» на практике: добавить в журнал или признать голосовую запись ошибкой.
4. Перевод сообщений: убрать из 1.0 или оставить с честной пометкой о качестве.
5. Подпись .exe сертификатом Windows (Authenticode): без неё Windows показывает
   предупреждение при первом запуске. Нужен сертификат организации.
6. Перевыпуск ключа GigaChat (после закрытой в 4.1 проблемы с настройками ИИ).
7. Кто со стороны ВСГУТУ получает root и дежурит.
