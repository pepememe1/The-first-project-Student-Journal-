Как зайти на сервер по SSH

Пароль не нужен. Вход по ключу: файл C:\Users\yaros\.ssh\gb_vps_ed25519 (без парольной фразы). Адрес и пользователь записаны в C:\Users\yaros\.ssh\config под коротким именем gb.

  1. Нажми Win + X → Терминал (или кнопку «Консоль сервера» и пропусти шаг 2).
  2. Набери и нажми Enter:
    ssh gb
  3. Появится строка вида root@cv7600409:~# — ты на сервере, с правами root.
  4. Выйти — exit или Ctrl + D.

Полная форма без алиаса (с другого компьютера, где лежит ключ):

ssh -i путь\к\gb_vps_ed25519 root@194.226.120.74

Ключ — единственный вход по SSH. Сохрани копию файла gb_vps_ed25519 в менеджер паролей или на флешку. Вход по паролю на сервере выключен намеренно: подобрать его нельзя.

Если SSH не пускает

  1. Зайди в панель reg.ru → твой VPS → Консоль (VNC в браузере).
  2. Логин gbadmin, пароль — тот, что я присылал 27.10 (храни в менеджере паролей; на сервере его больше нет). При вводе пароля символы не видны — это нормально.
  3. Стать root: sudo -i (пароль второй раз не спросит).
  4. Дальше — те же команды, что ниже.

Пароль root задавал reg.ru, нам он неизвестен. Понадобится — сброс в панели reg.ru. Вход в консоль сторож тревог тоже пришлёт письмом.

Письма на почту

  • Вечерняя сводка — каждый день в 17:00 по колледжу: активность, приманки, состояние сервера, защита (уязвимости, автообновления, тревоги за сутки).
  • Тревога — сразу: вход на сервер чужим ключом или паролем, вход в консоль reg.ru, упавшая служба, правка ключей и учёток, вход учёткой-приманкой, сайт не отвечает 3 минуты (сторож сам перезапустит и напишет, когда поднялось), кончается диск.

Пришло «Вход на сервер чужим ключом», а это не ты и не Влад: зайди в консоль reg.ru, посмотри cat /root/.ssh/authorized_keys, удали чужую строку, смени пароль gbadmin (passwd gbadmin) и напиши мне — разберём журнал.

Чего не делать

  • Не открывать в браузере служебные адреса сайта (/.env, /wp-admin и подобные): это приманки, они забанят твой адрес на сутки.
  • Не класть пароли в файлы на сервере.
  • Не удалять файл .gradebook_server.db.sync-anchor.json рядом с базой.
